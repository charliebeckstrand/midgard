# Map roadmap

> **Goal: a geography surface for logistics dashboards, on the chart module's hand-rolled SVG foundation.** The module ships `MapPlat` with two colour modes, one merged legend, a Tooltip readout, and a hidden data table. `MapRoute`, `MapPoint`, `MapMarker`, and `MapGeofence` draw over the geography, and the OSRM and Valhalla clients fetch street geometry. This file records what shipped, and what the foundation must absorb next.

## Status

The foundation is complete. The projection and geometry cores are pure and React-free, on d3-geo and topojson-client with the rest hand-rolled, and they now live with every other framework-free rule under [`engine/`](engine) (§Engine). The geometry arrives as a prop, either TopoJSON or GeoJSON, because the package ships no atlas data. The plat frame holds the legend and the visually-hidden table in plain HTML around a `role="img"` plot. The chart module's eight-slot palette reaches the marks through `kata/map`. The chart `animate` contract holds: the SVG is static by default, and the `motion/react` renderers are opt-in inside `ReducedMotion`.

Both colour modes ship. Categorical mode colours each region from a `categoryKey` value, in a fixed slot order. Numeric mode — the choropleth — bins a `valueKey` along a `colorRange` ramp, by equal interval or by quantile, and `MapRangeLegend` paints the continuous bar beside the plot. `ChoroplethChart` wraps that mode as a chart-family component. Both modes emit one meta-and-index shape, so the regions, the legend, the tooltip, and the table read either one unchanged. `MapPlatProps` holds the two modes' fields mutually exclusive, and the plat hands the readout its props whole rather than rebuilding them, so that exclusivity reaches the join intact.

The interaction grammar matches the chart module. Overlays register their own legend entries through context, so one legend switches regions and routes together: a point on an entry dims every other group, and a click toggles that group off. A point on a region or an overlay isolates the mark behind the same recede. The tooltip is the real Tooltip component on the map's own floating state; it anchors to the pointer and flips at the viewport edges.

The map is a picker that holds no state of its own. `onRegionClick` reports the clicked region's identity and index, in the shape the charts' `onCategoryClick` takes, and `onRegionContextMenu` reports the same pair for a menu that wraps the map. `selectedRegion` takes that identity back and rings the region above every layer, outside the hover recede, so a standing pick outlasts a passing emphasis. The region's table row reads as the current one. The map and the control beside it read one value, so the two can never disagree about the pick.

A picked overlay shows on the same terms. `selectedOverlay` takes the `{ id, index }` pair the marks report and haloes the mark it names: the mark's own shape in the selection ink, drawn behind it and outside its dim wrapper, so the colour reads through and the pick outlasts a passing hover — the region ring's discipline in the one form a stroke-painted mark allows (`map-halo.tsx`). A route and a marker's leg halo along their line, a point and a marker's pins behind the dot, and one ink serves all of them and the region ring alike. The index counts in the points a `MapPoints` was given, never in the dots it draws, so a pick that merged into a summary haloes that summary and separates onto its own dot as the frame widens around it. One rule resolves which stop a pick names (`engine/map-overlay/selection`), and the halo and the `aria-current` row both read it, so the picture and the readout can never mark different dots.

The pointer is no longer the only way in. The plot region is one arrow-navigable tab stop, on the chart module's model over a geography's own axes: an arrow steps to the nearest region that bears that way, Home and End jump to the ends of the atlas order, Enter or Space picks the region under the cursor, and Escape leaves and re-arms the next Tab. The cursor writes to the shared hover context, so the readout and the pointed-mark recede answer it through the path the pointer already uses. It earns its tab stop from either output, so a `tooltip={false}` picker stays reachable. No region path is focusable: the SVG stays `aria-hidden` under the `role="img"` plot, so a county atlas gains one stop, not three thousand. Both modules now share one exit rule (`use-plot-tab-stop`), because how a reader leaves a plot must never differ between them.

The overlays are pickable on the same terms. `MapRoute`, `MapPoint`, and `MapMarker` take an optional `id` and report it from `onClick` and `onContextMenu`, in the shape `onRegionClick` takes, so one map reports its geography and its marks the one way. An explicit id is also the legend key, so a mark keeps its colour and its toggled-off state across a remount. Each mark registers a keyboard anchor and its activation beside its legend entry, so the cursor steps regions and overlays as one field and Enter picks whichever it stands on — the plat dispatches without knowing what kind of mark it landed on. Both ride stable getters over a ref, so an inline handler or a route whose geometry lands late never re-registers, and the ledger never churns. The three marks now share one `useMapOverlay` for identity, registration, paint, and hit plumbing, which each had written separately.

`MapPoints` draws a set of dots under one registration, one legend row, one swatch and one toggle, for a fleet's stops or a chain's branches. The group is the mark — hovering any dot isolates the set, so two hundred dots draw under one wrapper and one dim class — while each dot keeps its own readout, its own keyboard stop, and its own pick, reported as the group's `id` and the dot's index. Against two hundred `MapPoint` children, which claim two hundred registrations and two hundred legend rows against an eight-slot palette, it mounts 3.3x faster: 5.0 ms against 16.3 ms. The tooltip and the visually-hidden table read one resolver (`engine/map-overlay/readout`), so the pointer and a screen reader can never disagree about a dot; the table carries a row per dot. The pointed mark is pinned at mark granularity, so sweeping between the dots of one set never republishes to every mark on the map.

`MapPoints` also summarises what the frame draws too close to tell apart. Dots inside a merge distance — a pixel distance, so the grouping answers the scale the map sits at and not the data — draw as one mark graded in size by how many stops it holds, with the count inside it: a national frame reads a metro round as one summary, and the same round separates into its own dots as the frame narrows onto the state. A summary is one mark to everything downstream — one tooltip, one keyboard stop, one table row, one pick — so the picture, the readout, and the cursor can never disagree about what is on the map, and a pick reports the first stop the summary holds so it still names a row the caller owns. One rule decides the grouping (`engine/map-cluster`): no two marks draw within `cluster`'s gap of one another, measured edge to edge so the one number holds however wide a summary grades up. Because merging moves a centre and widens the mark it moved, that rule is a fixpoint rather than a sweep — the pass repeats until nothing overlaps, which in practice is one round. A broad phase runs under it, grouping dots within a lone dot's own reach of a group's first member; it can only merge what the rule would merge anyway, so it takes the count down cheaply and never decides the result. Both passes bucket into the same grid at one cell per reach, so each mark reads the nine cells around it rather than every group built so far, and both walk that grid without allocating a candidate list. A set that never overlaps groups one dot per group, index for index with the points passed in, and `cluster={false}` skips every pass so an explicit opt-out draws each dot whatever it covers. Framing one region takes no new prop: hand the plat that region's own geometry and the fit it runs on every geography frames it, which is how the demo draws a picked state. That swap draws the region alone, so it answers a drill-down; the zoom below answers the other reading, and moves the view over the whole geography instead.

`zoom` opens the drawn geography to the reader, as a transform rather than a refit. One `<g>` over the whole drawing carries a scale and a translation in frame units (`engine/map-zoom/transform`), so the projection places the regions once and the layer moves what it placed: a gesture writes one attribute where a refit would reproject every path, and the region paths are byte-identical before and after. A wheel zooms about the pointer, a drag pans, two touches pan and pinch together — the midpoint's travel moves the view and the change in their spread scales it — and the plot's own tab stop takes `+`, `-`, and `0`, so a keyboard reaches every scale the pointer does and the arrow cursor pans the view to hold the stop it steps onto. The wheel rides a non-passive listener, because React registers `onWheel` passively and a passive handler cannot take the gesture from the page. A drag past four pixels swallows the click it ends on, so a pan across a clickable map never reports a pick the reader never made. Nothing on the map answers the pointer for the length of a gesture: a scaling frame sweeps the geography under a stationary pointer, and without that the wheel would drag the readout across every region and dot it crossed. A wheel reports no end, so the gesture's is read from a gap in the notches, and a pointer gesture and a settling wheel each wait for the other before the drawing comes back.

The page keeps every wheel the reader does not aim at the map, and the shift key is what aims it. Held, the wheel zooms and the page stays put; unheld, the plot scrolls past like anything else. Touch keeps the same bargain — `pan-x pan-y`, so one finger scrolls and two pan and pinch, and only the browser's own pinch, which would zoom the page over the map, is taken. That is the default because the other one fails silently and lands on the reader: a map dropped into a page that swallows a scroll strands whoever is scrolling, where a map that needs a key merely has to be learned. Only the shift key — a trackpad pinch arrives as `ctrl` + wheel and the platform's page zoom takes `ctrl` and `meta`, so either would fight for a gesture the reader means for something else — and a browser moves a shift-held wheel onto the horizontal axis, so the gesture is read from `deltaX` when the key is down and never otherwise, where a sideways delta is a scroll the page owns.

`{ modifier: false }` arms the wheel outright, for a map that owns its screen: a plain wheel zooms, the map hands the gesture back only where the view can no longer move — so a reader at the fit or at the ceiling still scrolls through it — and the plot claims touch, so one finger pans. It is the seldom-used opt-out, and it must be asked for. The whole reading of the prop is one function (`engine/map-zoom/input`), which is what lets the plat gate its tab stop and its touch policy without holding any view state.

The constraint is the fit itself. The scale floors at 1 — the projection already framed the geography, so zooming out past it could only letterbox what it framed — and the translate is clamped so the frame stays inside the scaled frame, which at the fit collapses to a point and re-centres the view without a second rule. A fixed `aspectRatio` letterboxes one axis and a pan can reach that band at the edge; it is the band the map already shows at rest, and ending it would need the geography's own projected bounds, which a passed `d3` instance has no cached canonical fit to derive without a bounds pass on the mount path. The view returns to the fit whenever the geography changes, because a new geography frames itself.

Constant-pixel discipline holds through the transform, which is what makes zooming in show more ground rather than a bigger picture of the same. Every stroke-painted spec was already a non-scaling stroke — region seams, route lines, the dots (drawn as zero-length round caps for this reason) and their haloes — so those pass through untouched; the route and marker hit bands join them, where they had scaled with the box before. What the layer would otherwise stretch takes one multiply by the units-per-pixel scale (`1 / k`), which the layer publishes beside the transform it applies (`MapZoomScaleContext`) because the two are one fact: the dots' hit circles, which are radii rather than strokes, and a summary's count, which sizes in user units and would climb out of the dot beneath it. A mark reads that scale off `useMapOverlay`, the seam all three already consume, so the rule reaches a new mark by construction rather than by memory. `MapPoints` takes it directly, ahead of its own registration, because the grouping decides what it registers: the rounds a national frame summarises separate into their own stops as the view closes on them, since the merge distance is a pixel distance and the transform is now part of what "drawn" means. That conversion happens once at the clustering pass's boundary, so its two phases compare in frame units alone.

The view state sits below the plat, in `MapZoomProvider` around the plot alone, for the reason `MapHoverProvider` does: a gesture writes on every wheel notch and every tracked pointer move, and held on the plat each of those would re-render it and re-plan its legend. Held there, the provider re-renders and the plat's stable plot element bails, so a notch reaches the layer, the plot region, and the marks that read the scale — the region layer holds its render through the whole gesture, and the legend, which answers the toggles and the emphasis rather than the view, sits outside the provider entirely. One bit says whether a map zooms at all: the context carries the whole gesture set or `null`, and the plat resolves the tab-stop gate from `mapZoomCeiling` on the prop without holding any view state. The pointer path measures the plot's box once at the press and holds it for the gesture, because reading it per move would force a layout pass over the region tree right after the move before it wrote the layer's transform.

`MapGeofence` draws the zone the other marks sit inside — a delivery area, a service radius, a district — as a wash under its own boundary. A circle takes a centre and a ground radius in metres. `circleRing` turns that pair into a ring on `d3-geo`'s own small circle (`engine/map-geofence.ts`), because a ring stepped in degrees reads as an ellipse away from the equator and breaks at a pole. A polygon takes its own ring instead, for a territory that answers no radius. Either way the mark is one closed path, and the wash, the boundary, the hit stroke, and the halo all trace that one string, so no two of them can diverge. The radius is the one measurement in the module that is not a device-pixel one: a zone covers the same ground however far out the map sits, while its boundary rides pixels like every other stroke. The whole face answers the pointer, plus a 24px band around the boundary — WCAG 2.5.8's minimum, which a line takes whatever is pointing, declining the 44px a dot claims on a coarse pointer because a band that wide would swallow a parallel leg — a zone is a place, so pointing anywhere inside it names it. That costs the marks it encloses nothing: they draw after it, and the topmost shape at a point wins, so a stop inside a zone still takes its own hover. It does cost the region under it, which the zone now covers for the pointer's purposes — the honest trade, since the zone is what the pointer is on there. A dot's own target answers the input device, so a zone drawn tight around a point stays reachable: the `r` attribute carries WCAG 2.5.5's 44px for a finger and `kata/map`'s `hitFine` takes it to 2.5.8's 24px for a mouse — the `TouchTarget` primitive's rule, in the one form an SVG shape allows, since only CSS can read the modality. One props factory sets it for every dot target (`dotHitProps`) rather than a component per dot: a fiber each priced two hundred of them at ~1.6 µs apiece, on a set that re-renders at every pointed-mark crossing. Its swatch is the region's `rect`, since the mark is an area too, and `MapSwatchShape` in `engine/types.ts` now names all three swatch shapes for the legend and the tooltip at once. The ring's path and its keyboard anchor sit in `map-geometry/mark.ts` beside the polyline's, over the projection walk both now share; the anchor reads the vertices rather than the enclosed area, so a backwards ring cannot centre it on the far side of the earth.

That navigation costs the mount nothing. The centroids the cursor steps by are geographic, not projected, so one pass per atlas serves every fit — but the pass measures every ring in the atlas (~30 ms across 3,000 counties, against a ~70 ms mount), so the plat hands the hook a closure and the hook resolves it on the first arrow key. The mount benchmarks cannot see this: they warm the cross-instance caches before they count, so the pass would be paid off-camera. [`boundary/map-centroid-deferral`](../../__tests__/boundary/map-centroid-deferral.test.tsx) counts the calls instead, and gates the mount, the re-render, and the resize paths at zero.

Three optimisations hold the mount cost down, and four browser benches gate them. `staticMapGeometry` memoises the decode, the canonical fit, and the canonical paths across instances and mounts, keyed on the atlas identity. `scaleCanonicalFit` derives the measured fit from the canonical one by arithmetic, so a resize never re-projects the bounds. The region layer resolves one paint per category and delegates its pointer handlers, so the base tree holds its render while the pointer travels and only the lit copies repaint. `map-mount`, `map-update`, `map-hover`, and `map-emphasis` measure all three.

The module's four outsized files split along the seams their own prose already named. `map-plat.tsx` is now its props type and the assembly alone: the geometry (`use-map-shape`), the row-to-bin join (`use-map-region-readout`), the data union both of those and the props read (`map-region/data`), the legend resolution (`map-legend/plan`), the pointer state (`map-hover-provider`), the shell (`map-frame`), and the legend's box (`map-legend-region`) each came out to stand on their own. The region layer's paint table (`map-region/paint`) and lit overlay (`map-regions-lit`) came out of `map-regions.tsx` on the same rule, and the clustering split three ways — the grouping passes, the grid they bucket into (`map-cluster/grid`), and the spherical readout (`map-cluster/geo`); the engine raise below took it to four. The shared scale-bar slider left the module for [`chart/engine/chart-legend/range-legend.tsx`](../chart/engine/chart-legend/range-legend.tsx), beside the placement resolver both colour-scaled charts already read; `map-range-legend.tsx` is the map's wrapper over it, and the slider is no longer on any barrel. `map-plat.tsx` stays the module's largest file, because roughly a quarter of it is the props doccomment that CONVENTIONS §12.1 requires.

The pure core is no longer flat. It was sixteen React-free modules interleaved with the components in one directory; it is now [`engine/`](engine), and the module root is the React shell — eighteen components, seven hooks, the contexts, and the barrel. A handful of private pure helpers still sit beside their one consumer there (`valueColumnHeader`, `bridgeRegionIdentity`, `regionDelegate`), which is what the grid and chart components do too; the engine holds every rule that more than one reader shares.

## Engine — the substrate

Every framework-free rule the map holds lives in [`engine/`](engine), a d3-shaped functional core laid out like the grid, chart, and query engines. Four leaves sit at its root — `types.ts` (the module's vocabulary, geographic `LngLat` beside frame `MapPoint2D`), `map-constants.ts`, `map-motion.ts`, and `map-geofence.ts` (the circle-to-polygon math, which is one kind and so earns no directory) — under which ten concept directories carry the rest: `map-geometry/` (the TopoJSON decode, the ring winding, the region paths and centroids, the mark paths and their anchors, and the cross-instance memo), `map-projection/` (resolution, the two-stage fit, the aspect and sizing policy, the frame-to-client conversion and its inverse), `map-cluster/` (the grouping pass and the rule it settles to, the size grade, the spatial grid, the spherical readout), `map-region/` (the data union, the region identity, the categorical and the numeric scale, the layer paint table), `map-overlay/` (the ledger entry, the readout, the pick), `map-hover/` (the hover-target algebra and the `data-*` anchor readers), `map-keyboard/` (the stop list, and the cursor the keys drive across it), `map-zoom/` (the view transform, its constraint, the ceiling a prop asks for, and the gestures that move it), `map-legend/` (the plan and the entries), and `map-routing/` (the polyline codec, the shared result, the request signal, the two clients).

Two files split by layer rather than by concept, so the engine owns its own vocabulary. `context.ts` kept the React contexts and gave up the target comparisons and the anchor readers, which need no React; `use-map-legend-registry.ts` kept the hook and gave up the `MapOverlayEntry` shape its ledger holds. The cursor, the readout, and the selection resolve against those without reaching back at the module root.

The layering invariant is grid's, verbatim — no `'use client'`, no runtime `react` / `motion` / `@dnd-kit` / `@floating-ui` imports, no runtime imports from the module root, no `index` barrel (the engine is imported file-by-file).

No reach outward stands: the engine names nothing from the module root, at runtime or in a type. The range bar's shape is the engine's own (`map-legend/plan.ts`'s `MapLegendRange`), which [`map-range-legend.tsx`](map-range-legend.tsx) takes as its props, so the arrow runs view → engine.

Two suites make the layout a gate rather than a convention. [`module-filename-boundary.test.ts`](../../__tests__/boundary/module-filename-boundary.test.ts) enforces the names — `map-*` directly under `engine/`, short kind names inside a `map-<concept>/` directory, no nesting — and [`engine-purity-boundary.test.ts`](../../__tests__/boundary/engine-purity-boundary.test.ts) enforces the four rules above for the grid, query, and map engines at once. That test replaces the greps this section used to carry, and the same paragraph in the grid and query ROADMAPs: a rule three documents asserted in prose is now asserted once in code, and it carries self-checks proving each rule can still fail.

The public surface was unchanged across the move: every barrel export keeps its name, and every function moved verbatim, so `ChoroplethChart`, the docs demo, the a11y corpus, and the benchmark suites read the same map they did before.

## Backlog

In priority order. Each entry names the gap, the shape of the fix, and where it lands.

- **The choropleth's props cast.** The plat takes the region-data union whole now, but `ChoroplethChart` still assembles the plat's props field by field and asserts them with `as Parameters<typeof MapPlat<T>>[0]` ([`choropleth-chart.tsx`](../chart/choropleth-chart/choropleth-chart.tsx)), because its own `idKey`, `colorKey`, and `colorRange` are each optional and it holds no whole object to pass on. Swap the assertion for `satisfies` and it fails on `regionKey`, so the cast carries weight rather than decorating. The plat's own fix does not reach it: keeping an object whole needs an object that is whole already. The shape is a narrowing constructor beside the union in [`engine/map-region/data.ts`](engine/map-region/data.ts), which takes the loose fields and returns a branch or the data-less map; the plat's path stays as it is.

- **A mark-safe fit — a theory about the projection, to be proved before it lands.** `fitSize` maps the geography's bounding box onto the frame exactly, so a mark on an extremum is centred on the boundary and half of it draws outside: on a 474-wide frame of Texas the westernmost stop centres at x 4.98 against a 5.5 radius, and a selection halo takes that reach to 8.5; a region border loses half its stroke at the same edge. Overflow is not the answer — six ancestors clip that SVG in the docs shell alone, two of them the page's own containers rather than the module's, and the plot box's clip is load-bearing for the resize seam ([`chart-plot-box.tsx`](../chart/engine/chart-plot-box.tsx)). The shape is `fitExtent` over `fitSize`, inset by one constant — a dot and its halo — in device pixels after `scaleCanonicalFit`, never in the canonical frame, where the inset would scale with the box and vanish at small sizes; deriving it from the registered overlays instead shifts the geography a beat after mount, the reflow the reserve exists to prevent. It moves every projected coordinate on every map, which is the module's widest blast radius, so prove it against the composite projection's insets, `staticMapGeometry`'s cross-instance cache, `scaleCanonicalFit`'s arithmetic derivation, each `aspectRatio` mode, and the deferred-centroid boundary, then re-run the four mount benches — the fit sits on the mount path. A top-grade summary on an extremum still shaves under one constant; say so in the doc rather than sizing the whole frame for it.

- **Routing failure reasons.** `fetchOsrmRoute` and `fetchValhallaRoute` return `null` for every failure. A timeout, a 504 from the rate-limited demo server, a malformed payload, and a genuine no-route answer all read the same, so a caller cannot tell a retry from a dead end. Return a reason beside the result.

- **Graticule and sphere chrome.** Optional meridian and parallel hairlines, and an outline for a world map, on the chart gridline inks.
