# Map roadmap

> **Goal: a geography surface for logistics dashboards, on the chart module's hand-rolled SVG foundation.** The module ships `MapPlat` with two colour modes, one merged legend, a Tooltip readout, and a hidden data table. `MapRoute`, `MapPoint`, `MapMarker`, and `MapGeofence` draw over the geography, and the OSRM and Valhalla clients fetch street geometry. This file records what shipped, and what the foundation must absorb next.

## Status

The foundation is complete. The projection and geometry cores are pure and React-free, on d3-geo and topojson-client with the rest hand-rolled, and they now live with every other framework-free rule under [`engine/`](engine) (§Engine). The geometry arrives as a prop, either TopoJSON or GeoJSON, because the package ships no atlas data. The plat frame holds the legend and the visually-hidden table in plain HTML around a `role="img"` plot. The chart module's eight-slot palette reaches the marks through `kata/map`. The chart `animate` contract holds: the SVG is static by default, and the `motion/react` renderers are opt-in inside `ReducedMotion`.

Both colour modes ship. Categorical mode colours each region from a `categoryKey` value, in a fixed slot order. Numeric mode — the choropleth — bins a `valueKey` along a `colorRange` ramp, by equal interval or by quantile, and `MapRangeLegend` paints the continuous bar beside the plot. `ChoroplethChart` wraps that mode as a chart-family component. Both modes emit one meta-and-index shape, so the regions, the legend, the tooltip, and the table read either one unchanged. `MapPlatProps` holds the two modes' fields mutually exclusive, and the plat hands the readout its props whole rather than rebuilding them, so that exclusivity reaches the join intact.

The chart-family wrapper reaches that union through a constructor rather than a cast. `ChoroplethChart` states its scale in a `series`, and `series[0]` is possibly absent under `noUncheckedIndexedAccess`, so each field it read out one at a time widened by `undefined` and the object it assembled matched no branch — which is why it asserted its props where the plat had stopped needing to. `numericRegionData` (`engine/map-region/data`) tests the four fields the numeric branch requires together and returns that branch or the data-less map, so the call site spreads a whole branch and its props are checked (`satisfies`) rather than asserted. Keeping an object whole needs an object that is whole already; the constructor is where one is made. A series-less choropleth now draws as the data-less map it always looked like — the cast had let its rows reach the plat without a join key, which published a headerless table of region names against empty value cells, a state the union names nowhere and only the cast could reach. The `legend` prop rides that union too, because one of its forms is a mode rather than a preference: `'range'` swaps the binned switchboard for the continuous scale bar, and only the numeric branch has a scale to paint on one. It sat in the plain-object half of the props before, so `legend="range"` type-checked on a categorical plat and then drew the switchboard at the categorical default — the one mode-dependent field the union did not hold, against eight illegal combinations a probe proved it refuses. The two switchboard forms stay on all three branches; only the bar is the numeric branch's own. `numericRegionData` carries it across: a placement is a layout the caller asked for and holds whether a scale landed, while a range request on a series-less choropleth is dropped there rather than by the resolver, which is the same silence one layer earlier and the layer where it keeps the result inside a branch. `isRangeLegend` is the one rule for what counts as a request, now a predicate so the drop needs no cast, read by the type that refuses the form and the resolver that draws it alike.

The frame carries optional chrome. `graticule` rules meridians and parallels under the geography — `true` takes d3-geo's ten-degree step, and a number sets its own — and `sphere` outlines the globe's own edge, the frame a whole-world map closes itself with. Both draw beneath every region on the chart's own chrome inks (`kata/map`'s `chrome`: the gridline hairline, and the axis baseline a step firmer), so a region fill covers the lines that cross it and the chrome reads around the geography rather than across it. Neither answers a pointer, joins the readout, nor takes a legend row, because chrome names no place and carries no value. The lines cover the globe whatever the geography frames and the viewBox clips the rest, so a one-state map's graticule pays a world map's pass — the worst case, not a property, and the reason both parts are off by default and a step under one degree is floored where it resolves (`engine/map-geometry/chrome`). The pass is memoised on the fitted projection rather than on the geometry, because a mount draws chrome under two fits — the canonical one on the first commit, the measured one a beat later — and one slot per geometry would have them evict each other, paying the pass twice on every mount and holding it across none. The canonical projection is itself shared across instances and mounts, so its chrome is drawn once per atlas and step for good. The whole resolution sits in its own memo rather than the geography's, so a chrome toggle never rebuilds the view — which would hand the context a fresh projector and recompute every overlay mark on the map to draw a hairline.

Chrome rides the view transform with everything else it rules. A meridian is a position on the globe like any region, so it draws in frame units under the zoom group and travels and scales with the geography rather than hanging over a map moving beneath it; its hairlines convert their width by the same units-per-pixel multiply every other spec takes, so the transform stretches the ground they rule and never the lines, and a zoom redraws no path — the layer stretches what the fit already resolved.

One path answers both parts, because the graticule draws only where the projection does. A composite has no single globe edge — `albers-usa` draws its own three clip frames, the lower-48 box and the two insets — and it streams the graticule through all three of its sub-projections, so an unbounded graticule fills each inset with fragments at its own angle and the map reads as three graticules laid over one another. Clipping the lines to that same frame path under the even-odd rule, where the inset boxes read as holes in the outer one, leaves the main map ruled and every inset clear. A whole-globe projection has one frame and no holes, so the same clip changes nothing there, and `sphere` strokes the path the graticule was already bounded by — the bound and the outline can never disagree about where the projection draws.

The docs draw both parts on a world atlas. `world-atlas` joins `us-atlas` as a dev dependency, and the World tab fetches its countries as a static asset on the react-query path the other tabs already run. The tab hands the plat that topology whole, because nothing there reads one country out of it — the other form `geography` takes, which the state demos cannot show. Equal Earth and Mercator each rule their meridians and outline their own edge, so the two world projections and `sphere` now have a demo to stand in. Each map frames at a ratio of its own, because the globe stands outside the box the fit maps onto the frame. Mercator takes 9/10, taller than the land's own 1.04: it cuts at 85°N, the northernmost land is Greenland at 83.6°N, and the top edge of the outline needs that margin. Equal Earth takes 5/2, wider than the land's own 2.03: no land reaches the antimeridian at the equator, where the globe is widest, so the land's own ratio cuts the outline between 16°S and 16°N. Neither map carries rows or marks, and neither takes a tab stop — the rule the tab below the demo drove out.

The interaction grammar matches the chart module. Overlays register their own legend entries through context, so one legend switches regions and routes together: a point on an entry dims every other group, and a click toggles that group off. A point on a region or an overlay isolates the mark behind the same recede. The tooltip is the real Tooltip component on the map's own floating state; it anchors to the pointer and flips at the viewport edges.

The map is a picker that holds no state of its own. `onRegionClick` reports the clicked region's identity and index, in the shape the charts' `onCategoryClick` takes, and `onRegionContextMenu` reports the same pair for a menu that wraps the map. `selectedRegion` takes that identity back and rings the region above every layer, outside the hover recede, so a standing pick outlasts a passing emphasis. The region's table row reads as the current one. The map and the control beside it read one value, so the two can never disagree about the pick.

A picked overlay shows on the same terms. `selectedOverlay` takes the `{ id, index }` pair the marks report and haloes the mark it names: the mark's own shape in the selection ink, drawn behind it and outside its dim wrapper, so the colour reads through and the pick outlasts a passing hover — the region ring's discipline in the one form a stroke-painted mark allows (`map-halo.tsx`). A route and a marker's leg halo along their line, a point and a marker's pins behind the dot, and one ink serves all of them and the region ring alike. The index counts in the points a `MapPoints` was given, never in the dots it draws, so a pick that merged into a summary haloes that summary and separates onto its own dot as the frame widens around it. One rule resolves which stop a pick names (`engine/map-overlay/selection`), and the halo and the `aria-current` row both read it, so the picture and the readout can never mark different dots.

The pointer is no longer the only way in. The plot region is one arrow-navigable tab stop, on the chart module's model over a geography's own axes: an arrow steps to the nearest region that bears that way, Home and End jump to the ends of the atlas order, Enter or Space picks the region under the cursor, and Escape leaves and re-arms the next Tab. The cursor writes to the shared hover context, so the readout and the pointed-mark recede answer it through the path the pointer already uses. It earns its tab stop from either output, so a `tooltip={false}` picker stays reachable — and it earns one from an output that exists rather than from a prop that asked. `tooltip` is a request. A map no row matches and no mark draws on falls silent on all three channels at once: the tooltip resolves nothing for an unmatched region, the pointed-emphasis gate lights nothing there because isolating the neutral fill would read as broken, and the table drops with them. So the gate reads the join — a region the rows matched, or a registered overlay — and a backdrop map takes no stop rather than one that answers every key with nothing. The pointer channel it had left behind is gated now too, on the region half of that same join: a backdrop map's region paths carry no move handler at all, where every pixel of every crossing used to commit hover state, re-render the provider, and re-render a Tooltip whose resolver returns `null` for each of the regions it was pointed at — 6,286 handler props on a counties frame, for a cascade that ends where it starts. The region layer reads that half alone rather than the whole reading the table and the tab stop take, and must: an overlay registers from an effect, so a bit counting one would flip a beat after mount, fail the layer's memo, and re-map the atlas a second time. Two predicates over one join — and a map that gains rows after its mount re-arms every channel, because each gate is a derivation of the join rather than a fact about the mount. A pick or a zoom still earns one, because each is an output of its own, and a legend toggle never takes one away: the silence a toggle makes is transient, and focus must not move under the reader. The World tab found it, which is what a demo of the undemonstrated is for. No region path is focusable: the SVG stays `aria-hidden` under the `role="img"` plot, so a county atlas gains one stop, not three thousand. Both modules now share one exit rule (`use-plot-tab-stop`), because how a reader leaves a plot must never differ between them.

The overlays are pickable on the same terms. `MapRoute`, `MapPoint`, and `MapMarker` take an optional `id` and report it from `onClick` and `onContextMenu`, in the shape `onRegionClick` takes, so one map reports its geography and its marks the one way. An explicit id is also the legend key, so a mark keeps its colour and its toggled-off state across a remount. Each mark registers a keyboard anchor and its activation beside its legend entry, so the cursor steps regions and overlays as one field and Enter picks whichever it stands on — the plat dispatches without knowing what kind of mark it landed on. Both ride stable getters over a ref, so an inline handler or a route whose geometry lands late never re-registers, and the ledger never churns. The three marks now share one `useMapOverlay` for identity, registration, paint, and hit plumbing, which each had written separately.

`MapPoints` draws a set of dots under one registration, one legend row, one swatch and one toggle, for a fleet's stops or a chain's branches. The group is the mark — hovering any dot isolates the set, so two hundred dots draw under one wrapper and one dim class — while each dot keeps its own readout, its own keyboard stop, and its own pick, reported as the group's `id` and the dot's index. Against two hundred `MapPoint` children, which claim two hundred registrations and two hundred legend rows against an eight-slot palette, it mounts 3.3x faster: 5.0 ms against 16.3 ms. The tooltip and the visually-hidden table read one resolver (`engine/map-overlay/readout`), so the pointer and a screen reader can never disagree about a dot; the table carries a row per dot. The pointed mark is pinned at mark granularity, so sweeping between the dots of one set never republishes to every mark on the map.

`MapPoints` also summarises what the frame draws too close to tell apart. Dots inside a merge distance — a pixel distance, so the grouping answers the scale the map sits at and not the data — draw as one mark graded in size by how many stops it holds, with the count inside it: a national frame reads a metro round as one summary, and the same round separates into its own dots as the frame narrows onto the state. A summary is one mark to everything downstream — one tooltip, one keyboard stop, one table row, one pick — so the picture, the readout, and the cursor can never disagree about what is on the map, and a pick reports the first stop the summary holds so it still names a row the caller owns. One rule decides the grouping (`engine/map-cluster`): no two marks draw within `cluster`'s gap of one another, measured edge to edge so the one number holds however wide a summary grades up. Because merging moves a centre and widens the mark it moved, that rule is a fixpoint rather than a sweep — the pass repeats until nothing overlaps, which in practice is one round. A broad phase runs under it, grouping dots within a lone dot's own reach of a group's first member; it can only merge what the rule would merge anyway, so it takes the count down cheaply and never decides the result. Both passes bucket into the same grid at one cell per reach, so each mark reads the nine cells around it rather than every group built so far, and both walk that grid without allocating a candidate list. A set that never overlaps groups one dot per group, index for index with the points passed in, and `cluster={false}` skips every pass so an explicit opt-out draws each dot whatever it covers. Framing one region takes no new prop: hand the plat that region's own geometry and the fit it runs on every geography frames it, which is how the demo draws a picked state. That swap draws the region alone, so it answers a drill-down; the zoom below answers the other reading, and moves the view over the whole geography instead.

`zoom` opens the drawn geography to the reader, as a transform rather than a refit. One `<g>` over the whole drawing carries a scale and a translation in frame units (`engine/map-zoom/transform`), so the projection places the regions once and the layer moves what it placed: a gesture writes one attribute where a refit would reproject every path, and the region paths are byte-identical before and after. A wheel zooms about the pointer, a drag pans, two touches pan and pinch together — the midpoint's travel moves the view and the change in their spread scales it — and the plot's own tab stop takes `+`, `-`, and `0`, so a keyboard reaches every scale the pointer does and the arrow cursor pans the view to hold the stop it steps onto. The wheel rides a non-passive listener, because React registers `onWheel` passively and a passive handler cannot take the gesture from the page. A drag past four pixels swallows the click it ends on, so a pan across a clickable map never reports a pick the reader never made. Nothing on the map answers the pointer for the length of a gesture: a scaling frame sweeps the geography under a stationary pointer, and without that the wheel would drag the readout across every region and dot it crossed. A wheel reports no end, so the gesture's is read from a gap in the notches, and a pointer gesture and a settling wheel each wait for the other before the drawing comes back.

The page keeps every wheel the reader does not aim at the map, and the shift key is what aims it. Held, the wheel zooms and the page stays put; unheld, the plot scrolls past like anything else. Touch keeps the same bargain — `pan-x pan-y`, so one finger scrolls and two pan and pinch, and only the browser's own pinch, which would zoom the page over the map, is taken. That is the default because the other one fails silently and lands on the reader: a map dropped into a page that swallows a scroll strands whoever is scrolling, where a map that needs a key merely has to be learned. Only the shift key — a trackpad pinch arrives as `ctrl` + wheel and the platform's page zoom takes `ctrl` and `meta`, so either would fight for a gesture the reader means for something else — and a browser moves a shift-held wheel onto the horizontal axis, so the gesture is read from `deltaX` when the key is down and never otherwise, where a sideways delta is a scroll the page owns.

The key arms the stream and does not end it. A trackpad keeps sending after the fingers leave, so letting go mid-coast used to drop the rest of that momentum on the page, which scrolled a little under a reader who had only stopped zooming — the map returned every unarmed wheel, and by then the tail was unarmed. So the map holds what the key armed until the stream itself ends: the tail is swallowed, and swallowed is all it is, because the release is what stops the zoom. Momentum only ever decays, and that decay is the only sign a wheel gives that anything is coasting at all, so a stream has to show it before the map keeps a tail off it: the first push after the key goes must be strictly smaller (`wheelPush` measures a push across both axes, since the release moves the stream back off `deltaX`). Once a stream has shown it, the plateau the decay rounds down to is held with it, because by then the figure it repeats is the pixel or two that would otherwise scroll. A mouse notch reports a fixed delta whatever the hand does, so a wheel that never runs down is never taken — a reader who lets the key go and keeps turning it has the page, which is the whole bargain the key buys. A push that grew ends the claim the same way. The stream ends on the same gap the gesture does (`MAP_WHEEL_SETTLE_MS`), so a wheel after a pause never meets a claim left standing.

`{ modifier: false }` arms the wheel outright, for a map that owns its screen: a plain wheel zooms, the map hands the gesture back only where the view can no longer move — so a reader at the fit or at the ceiling still scrolls through it — and the plot claims touch, so one finger pans. That rule stands where the stream rule above does not, and the difference is the key: a tail is only ever stranded by a hand leaving a key mid-coast, and this mode has no key to leave, so holding a stream here could only take the fall-through that keeps a reader from being trapped on the map. It is the seldom-used opt-out, and it must be asked for. The whole reading of the prop is one function (`engine/map-zoom/input`), which is what lets the plat gate its tab stop and its touch policy without holding any view state.

The constraint is the fit itself. The scale floors at 1 — the projection already framed the geography, so zooming out past it could only letterbox what it framed — and the translate is clamped so the frame stays inside the scaled frame, which at the fit collapses to a point and re-centres the view without a second rule. A fixed `aspectRatio` letterboxes one axis and a pan can reach that band at the edge; it is the band the map already shows at rest, and ending it would need the geography's own projected bounds, which a passed `d3` instance has no cached canonical fit to derive without a bounds pass on the mount path. The view returns to the fit whenever the geography changes, because a new geography frames itself.

Constant-pixel discipline holds through the transform, which is what makes zooming in show more ground rather than a bigger picture of the same. Everything the layer would otherwise stretch takes one multiply by the units-per-pixel scale (`1 / k`), which the layer publishes beside the transform it applies (`MapZoomScaleContext`) because the two are one fact: every stroke width — region seams, route lines, the dots (drawn as zero-length round caps, whose width is the disc) and their haloes — plus the hit circles, which are radii rather than strokes, the route and marker hit bands, and a summary's count, which sizes in user units and would climb out of the dot beneath it. The stroke-painted half rode `vector-effect="non-scaling-stroke"` first, which asked the browser for that conversion instead of taking it: it put the drawn size of every mark on a stroke transform the module cannot reach, and a `pathLength` dash under one covers `1 / k` of its path, so a zoomed route lost its far end. The region seams state their width once on the layer's own group and every path beneath inherits it, because restating it per path would put a whole atlas through React on each notch. One spec reaches its shape as a CSS length rather than an attribute, because it answers a media query no attribute can — the dots' fine-pointer target. CSS wins over the attribute, and a CSS length on an SVG shape is a user unit, so that target takes the same division through a custom property `dotHitProps` sets per shape (`kata/map`'s `hitRadius`). Untouched, it grew with the view: a 43.8px radius at the 8× ceiling behind a dot drawn at 5.5px, so past 4× a mouse claimed more ground than a finger, and a pair of stops the zoom had just parted sat 14.9px apart under targets that wide. The property rides each shape rather than the layer above them all, for the reason that factory states. A mark reads that scale off `useMapOverlay`, the seam all three already consume, so the rule reaches a new mark by construction rather than by memory. `MapPoints` takes it directly, ahead of its own registration, because the grouping decides what it registers: the rounds a national frame summarises separate into their own stops as the view closes on them, since the merge distance is a pixel distance and the transform is now part of what "drawn" means. That conversion happens once at the clustering pass's boundary, so its two phases compare in frame units alone.

The view state sits below the plat, in `MapZoomProvider` around the plot alone, for the reason `MapHoverProvider` does: a gesture writes on every wheel notch and every tracked pointer move, and held on the plat each of those would re-render it and re-plan its legend. Held there, the provider re-renders and the plat's stable plot element bails, so a notch reaches the layer, the plot region, and the marks that read the scale — the region layer holds its render through the whole gesture, and the legend, which answers the toggles and the emphasis rather than the view, sits outside the provider entirely. One bit says whether a map zooms at all: the context carries the whole gesture set or `null`, and the plat resolves the tab-stop gate from `mapZoomCeiling` on the prop without holding any view state. The pointer path measures the plot's box once at the press and holds it for the gesture, because reading it per move would force a layout pass over the region tree right after the move before it wrote the layer's transform.

`MapGeofence` draws the zone the other marks sit inside — a delivery area, a service radius, a district — as a wash under its own boundary. A circle takes a centre and a ground radius in metres. `circleRing` turns that pair into a ring on `d3-geo`'s own small circle (`engine/map-geofence.ts`), because a ring stepped in degrees reads as an ellipse away from the equator and breaks at a pole. A polygon takes its own ring instead, for a territory that answers no radius. Either way the mark is one closed path, and the wash, the boundary, the hit stroke, and the halo all trace that one string, so no two of them can diverge. The radius is the one measurement in the module that is not a device-pixel one: a zone covers the same ground however far out the map sits, while its boundary rides pixels like every other stroke. The whole face answers the pointer, plus a 24px band around the boundary — WCAG 2.5.8's minimum, which a line takes whatever is pointing, declining the 44px a dot claims on a coarse pointer because a band that wide would swallow a parallel leg — a zone is a place, so pointing anywhere inside it names it. That costs the marks it encloses nothing: they draw after it, and the topmost shape at a point wins, so a stop inside a zone still takes its own hover. It does cost the region under it, which the zone now covers for the pointer's purposes — the honest trade, since the zone is what the pointer is on there. A dot's own target answers the input device, so a zone drawn tight around a point stays reachable: the `r` attribute carries WCAG 2.5.5's 44px for a finger, and `kata/map`'s `hitFine` narrows it for a mouse in the one form an SVG shape allows, since only CSS can read the modality. The floor is the drawn dot, because a target inside its own mark would leave the mark a dead rim, and that figure sits under 2.5.8's minimum on purpose — `POINT_HIT_RADIUS_FINE` states why. A mouse pays the precision only where the pixels have somewhere to go, which is the second half of the rule: a dot gives reach back to a drawn zone it stands on, to a neighbouring dot inside that reach (`neighbourRoom`, over the grid the clustering already buckets into), or to the region layer beneath it wherever that layer answers the pointer at all — a matched region reads out under it, a click picks one, a right-click can open a menu on one, and a finger-sized target over any of the three is a 44px hole in it. Whether the layer answers at all is resolved once for the whole map (`regionPointerState`), and that resolver is also where a caller switches it off outright (`regionPointer`), which a drilled map does: the state under the dots is the ground they stand on and has nothing left to say, so the switch withdraws the readout, the pick, the menu, and the keyboard pick together and the dots above it take their whole target back. How much the layer claims is a share of the region rather than a figure (`AREA_SPARE_FRACTION`, `engine/map-region/spare.ts`), the same half a zone gives on the same `2 · area / perimeter` measure — one constant now, because regions are the harder case of what the zone half already learned. The figure this replaced was the drawn dot itself, and that was the small end charged to every region on every map: a state with room to spare took the same bite as one with none, so the dots on Texas were paying a county's precision, and a dot over open water paid it too. A region with room to spare now owes the dots on it nothing and they keep the full finger target; a region with nothing to spare drives the share back under the dot's paint, where `markTargets` floors it — so the small states end where they began, and what actually moved is the large ones and the open water. It is resolved per dot, which the map-wide reading could not do: no dot could ask what region it stood on, because the module resolves a region off a pointed DOM element and not off a coordinate. It can ask now — `map-geometry/locate.ts` already indexes an atlas by bounding box for the coverage frame, and the fit inverts, so a frame position becomes a lon/lat and the grid takes the candidates down to a handful. The measure is per region and lazy, and the vertices go to garbage once `areaReach` has walked them, since every reader after it wants the ring boxes alone. A dot answers to every region its target could cover rather than to the one it stands in, which is the zone rule's own reading, and the walk stops as soon as one region has driven the budget to the floor. The scale reaches the region half through the plat's resolver, which takes it as an argument `useMapOverlay` binds — the plat cannot bind it itself, since `MapZoomScaleContext` sits below it, and past that hook every reader takes the one-measure shape each claimant has always had. Read as clicks alone it under-claimed, and the coverage drill's tiled county maps are why it now reads wider — they take no county pick, since a pick could only be read back onto one of them, so every pin on them went on blanketing the readout underneath. None of the three under it, and the dot keeps the whole finger target on every pointer — a lone point on open geography was paying an 11px target for a zone that was not there, and a depot went on paying it after the legend put its catchment away. The zone half is a budget rather than a yes-or-no, because inside-or-out has no answer where the question is asked. A zone strung between the marks it holds puts every one of them on its own boundary: the Texas triangle's four metros are the ring's four vertices, and a ray cast at a vertex is decided by the winding and by which vertices the hull holds — so the three corners on the hull read as outside and took 22px while the reflex corner read as inside and took 5.5px, four dots of one set pointing two ways. A small zone failed the other way: every dot on it read as inside, and 22px of target blanketed a catchment 25px across. So a zone publishes how much room it has (`areaReach`, over the projected rings it paints) and a dot near it takes a share of that — half (`AREA_SPARE_FRACTION`), so the zone keeps at least as much as it gives, at every size and with no threshold to land on the wrong side of. The measure is `2 · area / perimeter`: the inscribed radius exactly for a circle, which `circleRing` makes most zones on a map, and the width rather than the diagonal of a long thin corridor, where a bounding box errs twentyfold. One budget for the whole zone rather than a measure per dot, because what a reader sees is four corners of one shape pointing alike. The budget is resolved once for the whole zone (`zoneBudget`) and the per-dot call only places the dot against it (`zoneSpare`, over the ring boxes `projectArea` already walked), because the resolver runs for every dot on the map against every visible zone — measured inline it walked every vertex of a dissolved territory once per dot, two hundred times over on the beat a wheel notch rebuilds them. Both sit in `engine/map-geofence.ts` beside `circleRing`, since the zone half of the rule is frame arithmetic like the other two thirds of it. It answers the plat's own ledger, so a legend toggle moves the targets under it: the geofence registers that budget beside its legend entry (`MapOverlayEntry.spare`, stable like `stopsAt` so a redrawn territory never re-sorts the ledger), the plat takes the tightest of the visible ones, and a mark asks it per dot. Every layer below the join spells "I claim nothing" as the identity of a minimum rather than as the finger target, so `markTargets` is the one place that knows what a target caps at and a third claimant needs to know only its own measure. The crowding half is the mark's own — a `MapPoints`'s drawn groups, a `MapMarker`'s pair of pins — because pooling every dot on the map would have to happen in the plat, and the plat cannot see the zoom scale those reaches are measured in: `MapZoomScaleContext` sits below it, around the plot alone, so that a wheel notch re-renders the marks without re-rendering the plat, its legend, and the region layer. Within a mark is also where a target swallowing a neighbour actually happens — the pair a zoom has just parted sits ~15px apart, well inside a 44px circle — and two separate marks that close each keep the full radius, the bound the pass accepts. `engine/map-cluster/ground.ts` answers that bound the other way, by dividing the overlap rather than shrinking either target: a dot's ground is its full circle minus whatever lies nearer to another mark's dot, so the boundary is the perpendicular bisector between the two, the outward three quarters keep their whole reach, and the contested middle divides once and evenly rather than going to whichever drew last — which is what it did, silently taking the underneath pin's tooltip with it. The cuts are straight and the arc is the circle's, so the target stays a `<circle>` under a `<clipPath>` holding a convex `<polygon>`; a half-plane intersection is convex however many neighbours crowd in, which is what makes the clip sound. It can pool across marks where the radius half cannot, because it measures in frame units and a frame position is scale-free where a device-pixel reach is not: the plat gathers every visible dot-drawing mark's stops once on the first read (`pooledDots`, held like `MapPoints`'s own `stopOf`, since the gather invokes every entry's `stopsAt` thunk) and each mark drops its own from the finished pool. Almost every dot on almost every map has no neighbour inside `2 · reach` and gets `null` back — no polygon, no `clipPath`, no id. `MapPoint` reads it today; wiring the plural marks to it is open, and per-dot `<defs>` is the thing to settle first, since one `<clipPath>` per summary would put back the fiber-per-dot cost `dotHitProps` exists to avoid. `markTargets` is where the two halves meet: both arrive as a reach in device pixels, so the answer is their minimum, floored at what the dot paints and capped at the finger target — and every dot-shaped mark reads that one rule, so a mark added later takes it by construction. A depot claimed the middle of its own zone at 24px too: a 150 km catchment projects to about 25px on a national frame, so the dot took a fifth of the zone's radius and the whole of it on a phone. It now takes half of what that catchment can spare, about 12px, and the ring outside answers the zone. The floor is the mark's own drawn radius rather than one figure for every dot, so a summary keeps the grade it draws at. One props factory sets all of it for every dot target (`dotHitProps`) rather than a component per dot: a fiber each priced two hundred of them at ~1.6 µs apiece, on a set that re-renders at every pointed-mark crossing. Its swatch is the region's `rect`, since the mark is an area too, and `MapSwatchShape` in `engine/types.ts` now names all three swatch shapes for the legend and the tooltip at once. The ring's path and its keyboard anchor sit in `map-geometry/mark.ts` beside the polyline's, over the projection walk both now share; the anchor reads the vertices rather than the enclosed area, so a backwards ring cannot centre it on the far side of the earth.

One place, one legend entry. A depot's catchment and the depot inside it are two marks and two registrations, so the legend counted a three-depot map as six entries and named each city twice — and "Los Angeles catchment" wrapped the side panel's 12rem column, which centred that entry's swatch against a three-line block while every other swatch sat on its first line. `MapOverlayProps.group` merges them: marks naming one group take a single entry, keyed with one swatch per distinct mark shape, so a square beside a dot says an area and a point without a word for either. The group's first-registered member names the entry and gives it its detail — the order a zone already has to be written in to draw behind the marks it holds — and the whole group takes that member's slot colour (`engine/map-overlay/slots.ts`, which advances the palette per entry rather than per mark), because two colours under one label read as two things and a group that ate a slot per member would exhaust an eight-slot palette on four places. The toggle expands once in the plat rather than at each reader: `hidden` carries the switchboard's own ids plus the members of any group switched off, so the region layer, the tooltip, the keyboard stops, the dot pool, and every mark's own `hidden` — which the zone budgets read through — go on asking the one question they already asked. The legend itself is handed the switchboard's own set, since an entry is what it draws. Only the emphasis resolves a group at the mark, since it is one id rather than a set. It groups the legend alone — each mark keeps its own tooltip, table row, and keyboard stop, because the pointer lands on a mark and not on a group. The entry itself lost the label-over-detail stack that a trailing readout used to cost a second line: the readout holds its own column beside the name at `size="sm"`, the type step the chart legend already sets, and the swatches align to the first line rather than to the middle of a wrapped block. The demo's rail reads three rows where it read thirteen lines.

`useMapCoverage` turns a ZIP-code territory into a map. A broker states coverage in codes rather than in ground, so the hook cuts that territory out of a ZCTA atlas, dissolves it into one shape, works out which states it lands in, and hands back those states' counties as the geography to draw. The plat fits whatever geography it is given, so the state frames itself through the drill-down the module already had and no projection rule was added. One selection feeds both halves — `geography` to the plat, `area` to a `MapGeofence` — so the ground drawn and the ground fenced can never disagree. The counties are the split and not the scope: they name themselves on hover and fill the table, while the fence carries the whole coverage reading.

The territory is a small language rather than a list. `606` is the ZIP3 a region is stated by, `60601-60640` and `600-609` are spans at either width, `60601-1234` is the ZIP+4 a masked field emits and reads as the code inside it, and a leading `!` subtracts — so `606, !60605` is a prefix less its exception. The terms parse out of one pasted string, and an unreadable one is reported rather than thrown, so a typo marks itself instead of voiding a territory. A prefix is a span and compiles to one — `606` is every code from `60600` to `60699`, which is what a stated range's ends already widen to — so the rules compile to a closure over a set of whole codes and one sorted list of merged spans, and each of an atlas's tens of thousands of codes is answered in one lookup and one bisect however many rules stand behind it. Codes compare as their five-digit strings, because a ZIP keeps its leading zeros and `01001` is a place where `1001` is nothing.

A topology dissolves exactly, which is why one is worth passing. TopoJSON holds each shared border once as an arc, so `merge` drops the arcs the covered codes share and keeps the ones only one of them holds: the seams between neighbours vanish, an uncovered code inside the territory comes out as a hole, and two clusters come out as two parts. Nothing is clipped and nothing is rounded, because the work is over the arc index rather than over coordinates. A feature collection cannot do that — it repeats every shared border as two independent runs — so it gathers each code's own rings instead, and `dissolved` reports which of the two happened.

That shape is what `MapGeofence` grew an `area` for. A dissolved territory is several polygons, any of which can enclose ground it leaves out, where the mark had taken one outer ring. The three geometries now meet in the widest one's shape before anything is drawn, so a circle and a lone boundary reach the path, the anchor, the wash, and the hit as the one-ring cases they are, and the mark still holds one of each. The wash and the hit shape fill under the even-odd rule, so a hole reads as a hole whichever way its ring winds — which is what lets a merged topology draw in the winding its own arcs gave it, with no rewinding pass — and a hole answers no pointer, so the region beneath it keeps its own hover. The keyboard anchor stands on the largest part rather than between them all, sized winding-blind, because a territory in two distant clusters has no middle that stands on it.

Most codes are placed without being measured. Every region whose bounding box meets a code's box is a region that code could sit in, so where all of them agree on one state no measurement can name another, and the code is settled for the cost of two boxes; only a code whose neighbourhood spans two states reads its own centroid. Against the 2010 Illinois ZCTA file that settles 1,187 of 1,384 codes on boxes alone and takes a ten-prefix territory's whole pass from 224 ms to 29 ms. It is also the sounder of the two rules: a centroid is a point, and it can land on water the county atlas does not draw — Chicago's 60611 centres in Lake Michigan — or fail to exist at all where a ring is degenerate at the atlas's own precision, which is what 61625 measures as `NaN`. Both place correctly on their boxes, and both would otherwise place nowhere.

The expensive passes answer the atlas rather than the territory, so typing into a coverage field re-cuts and re-dissolves alone. The frame it hands the plat is held on the states it names rather than on the territory that named them, because `MapPlat` keys its decode, its canonical fit, its region paths, and its chrome on that object's identity: a fresh collection per keystroke would re-project the whole county atlas twice per character and hit none of the caches built to stop exactly that. The decode is memoised across instances beside the mount-critical pair it was factored out of (`map-geometry/cache`), so a plat and the hook never decode one county atlas twice; the bounding-box grid the placement queries is memoised on the decoded features and built on the first read, so a map that places nothing never builds one. That grid is `map-geometry`'s rather than the coverage pass's, because nothing in it is ZIP-aware — placing a geocoded result or rolling a measure up by region asks the same question. That grid buckets a region by its corner cells rather than by its own width, because a box narrower than a cell still spans two of them wherever it crosses the line between — Cook County is 0.74° wide across the meridian the grid divides on, and bucketing by width alone left it missing from half its own ground. Rewinding sits with the measurement that needs it rather than at the cut, because it measures a spherical area per ring while the placement measures almost no codes at all, which took the cut of a 393-code territory from 61 ms to under 1 ms.

That navigation costs the mount nothing. The centroids the cursor steps by are geographic, not projected, so one pass per atlas serves every fit — but the pass measures every ring in the atlas (~30 ms across 3,000 counties, against a ~70 ms mount), so the plat hands the hook a closure and the hook resolves it on the first arrow key. The mount benchmarks cannot see this: they warm the cross-instance caches before they count, so the pass would be paid off-camera. [`boundary/map-centroid-deferral`](../../__tests__/boundary/map-centroid-deferral.test.tsx) counts the calls instead, and gates the mount, the re-render, and the resize paths at zero.

The routing clients name what stopped them. `fetchOsrmRoute` and `fetchValhallaRoute` answer `{ ok: true, route }` or `{ ok: false, failure }`, mutually exclusive in the type, so a caller that reads `ok` reaches one or the other without a second test. Seven kinds carry the whole taxonomy (`engine/map-routing/failure`): under two stops name no leg and send nothing, a signal ends a request as either the timeout the client set or the abort the caller asked for, a request reaches no answer, a status refuses one, a body parses as no routing answer, and the service itself refuses the pair. Each failure states whether asking again could answer differently, because "a retry or a dead end" is the one question a `null` could not answer: a timeout, a dead network, and a 5xx or a 429 from the rate-limited demo server can all clear, while a refused request, an unreadable body, and two points no road joins answer the same way however many times they are asked. An abort is the one kind that reads as neither — the caller ended that request itself, so whether to send another is a decision it already holds.

Two of those kinds are told apart by what the answer itself carries. A signal names itself in the reason it aborts with, and `AbortSignal.any` passes on the reason of whichever of the two fired, so `'timeout'` and `'aborted'` separate on a name rather than on which signal the client happens to hold. A service that cannot join a pair refuses in its own code under a 200 — OSRM answers `NoRoute` with no `routes` at all — so a code that is not `Ok` is the service's answer and reads as a refusal that carries that code, an empty `routes` array says the same thing without naming it, and a body with neither is not a routing answer whatever else it parsed as. The three failures that land before the payload are read once rather than once per service: both clients now send through one `routeFetch` (`engine/map-routing/request`) and keep only the url and the body their own service takes, so an OSRM leg and a Valhalla leg can never fail differently.

Three optimisations hold the mount cost down, and four browser benches gate them. `staticMapGeometry` memoises the decode and the canonical fit across instances and mounts, keyed on the atlas identity, with the paths that fit draws memoised beside it rather than on it. They resolve on their first read, because a `deferPaint` map never asks: it holds an empty frame until the container is measured and then draws from the measured fit alone, so a canonical pass would build paths nothing renders — 186.8 ms of a 327.1 ms static pass across 3,108 counties, on every chart `ChoroplethChart` draws, since it defers unconditionally. The paths are a memo of their own beside the measured ones (`cachedCanonicalPaths`), keyed on the geometry entry rather than held as a field on it — the shape the rest of that file already uses for work it defers. There is no property for a spread, a clone, or a key walk to force into existence, so the deferred branch skips the pass by not calling for it rather than by remembering not to touch it. [`boundary/map-path-deferral`](../../__tests__/boundary/map-path-deferral.test.tsx) counts the pass — zero for a deferred map, one for a map that paints before it is measured — because the mount benches warm the cache before they count and cannot see it. `scaleCanonicalFit` derives the measured fit from the canonical one by arithmetic, so a resize never re-projects the bounds. The region layer resolves one paint per category and delegates its pointer handlers, so the base tree holds its render while the pointer travels and only the lit copies repaint. `map-mount`, `map-update`, `map-hover`, and `map-emphasis` measure all three.

A fourth sits under them, on the cache miss the first exists to make rare. `canonicalFit` projected every coordinate twice: d3's `fitWidth` streams the geography at a probe scale and keeps only the scale and translate it derives from those bounds, so recovering the frame it had just held took a second pass over the drawn map. `fitProjectionWidth` (`map-projection/resolve`) takes the probe pass itself and applies d3's own arithmetic to it, which halves the fit — 218.8 ms to 94.4 ms across 3,108 counties on the `map-compute` bar, and 25.2 ms to 13.4 ms across 49 states. The frame is measured at probe scale now rather than at drawing scale, where adaptive resampling refines a curve differently; the two agree to the last bit on every atlas the suite draws, and `scaleCanonicalFit` accepts a divergence of that kind by name already. One test read the difference, and what it read was its own fixture: two stops 14.000000000000012px apart against a 14px merge distance, a case balanced on the threshold rather than clear of it, now spaced into the middle of the window it means to hold.

A fifth takes the same rule to the paths themselves, which is the larger half of what a fit costs. `regionPaths` streamed every coordinate through `d3-geo` afresh under each fit, and a map draws the atlas under two in one mount — the canonical fit on the first commit, the measured one a beat later — and under another on every resize: 246.3 ms apiece across 3,108 counties, against 160.4 ms to walk the geography and 12.8 ms to build the strings that walk ends in. So the walk happens once and its output is kept. `projectAtlas` (`map-geometry/projected`) streams the geography into a flat buffer of frame coordinates, and `emitRegionPaths` writes the `d` strings from that buffer under any later fit — reached by arithmetic, because a d3 projection places a point as `scale · raw + translate` and nothing else, so two fits of one projection differ by a scale and a translation on the frame. That is the fact `scaleCanonicalFit` already derives the measured fit itself from; the paths now ride it too, and they test it rather than trust it. The buffer keeps one witness position, and a fit that fails to place it where the affine says is refused instead of drawn from — so a `center`, a `rotate`, a per-axis factor, or a `postclip` reaching the emit costs a fallback rather than a wrong map, whether it arrives from a consumer's own projection or from a later edit to the fit this derives against.

The strings are the walk's own, byte for byte, wherever `d3-geo` would refine the geography the same way at both fits. `geoPath` resamples a curve until its chord sits inside a tolerance measured in frame units, so the buffer freezes the vertices its own fit earned: a distant frame would have earned others, more above and fewer below. Geography whose own vertices already sit inside that tolerance is refined at no fit and so matches at every one — which every real atlas is, being a quantised topology. [`map-geometry-projected`](../../__tests__/modules/map-geometry-projected.test.ts) pins both halves against `states-10m` under `albers-usa`, the atlas where an island state carries several rings, Alaska and Hawaii route to sub-projections of their own, and each inset clips: it matches the direct walk from a third of its canonical width to sixteen times it, where a four-vertex polygon parts from it. What parts is the density of points along a curve and never where one lands, so the gap reads as a straighter long edge, bounded by the tolerance the fit it was drawn at already accepted; the witness cannot see it, because a resampled vertex rides the same affine as every other.

Two cases stay on the direct walk, because the arithmetic rather than the buffer is what fails on them. A geography carrying anything but area rings is drawn by `d3-geo` from more than the ring vertices the buffer records — a point is an arc of its own radius, a line an unclosed run — so either would come back closed through its vertices, a different shape and not a rounder one. And a projection carrying an explicit `clipExtent` cuts in frame units that stay where they are when it is scaled, so one buffer read at two fits would keep two different pieces of the geography; the built-in projections all report none, and `albers-usa` carries no such method at all. `regionPaths` is the fallback all three refusals take, so geography the buffer declines draws the same map the slow way rather than no map at all.

The emit's own cost is formatting rather than arithmetic, and it is halved on the way. Of 22.4 ms across 3,108 counties the affine multiply is 1.4 ms and the concatenation 0.8 ms; the remaining 21.0 ms is turning doubles into strings, because at one decimal every value divides to a tenth that no double holds exactly and each takes V8's shortest-representation search. Formatting from the integer `Math.round` already produced, and placing the decimal point by hand, keeps the pass on integers: 22.4 ms to 12.8 ms on counties and 4.4 ms to 2.0 ms on 49 states, byte for byte the same strings.

The resize path is what all of it buys most. The measured slot holds one box, so a drag re-drew the whole atlas at every size it committed; it now emits them — 246.3 ms to 12.8 ms across 3,108 counties on the `map-compute` bar, and 33.4 ms to 2.0 ms across 49 states. A cold mount falls with it, since the canonical draw and the measured refit now share the one walk: the county mount reads 230.4 ms to 170.9 ms on `map-render`, and the states cold rung 94.2 ms to 80.0 ms. The steady-state competitive scenarios are unmoved and were expected to be — they warm the cross-instance caches before they count, so the pass this removes is already paid by the time they time anything, which is why `map-compute` gained a rung for it rather than the browser suite.

A sixth closes the pair the fourth and fifth left standing beside each other. The fit and the buffer were one walk apart over the same coordinates: `fitProjectionWidth` streamed the geography at a probe scale to read its bounds and kept only the scale and translate it derived, and `projectAtlas` then streamed it again to record where every point landed. But bounds are a scan of those same points, so `probeCanonicalFit` (`map-geometry/projected`) fills the buffer and measures the frame on its way out — 124.8 ms and 144.2 ms across 3,108 counties become 132.9 ms, and 16.1 ms and 18.1 ms across 49 states become 16.2 ms. The states cold rung reads 80.0 ms to 48.9 ms on `map-render`. d3's own fit arithmetic moved out of the pass that measures the bounds (`fitWidthFromProbeBounds`, `map-projection/resolve`) so the two ways of reaching those bounds place the result by one rule; `canonicalFit` keeps the walking pass for the geography and the projections the buffer declines.

The buffer is therefore drawn at probe scale and read at every fit above it, which is the resampling gap above pointed the other way and needs holding open. `PROBE_REFINEMENT` does it: the probe walk resolves a curve four times finer than d3's default, which puts the buffer at or past what the canonical frame would have earned on its own. It costs a real atlas nothing, because a quantised topology's own vertices already sit inside the finer tolerance — `counties-10m` streams the same 63,888 points at that precision as at the default, in the same time — and the frame comes out bit-identical (585.000128913205 either way) with every path byte for byte the walk's own, at the canonical frame and at 800, 317, and 3,840 wide. A passed instance gets its precision back afterwards, as `fitProjectionWidth` returns a clip it borrowed.

A seventh takes the refit off the paths altogether. The measured fit is a scale and a translation on the canonical one — the fact the fifth rides to emit its strings — so the paths the first commit already drew reach the measured frame under one group transform rather than being emitted again and written again. Rewriting 3,107 `d` attributes and forcing layout costs 47.1 ms in Chromium against 0.15 ms for one `transform`, and the emit that fed them (12.8 ms) is not paid either. A settled resize on a county atlas reads 88.96 ms to 53.95 ms, of which ~35 ms is the two animation frames the measurement waits out either way — so the work itself falls from ~54 ms to ~19 ms.

Only the region layer moves, which is what keeps the change narrow. The transform maps that layer's own frame onto the drawn one, so the overlays, the chrome, and every hit target stay in the measured units they are placed in, and the two coordinate systems land on the same device pixels. Its inherited seam and the selection ring divide by the frame's scale on top of the zoom scale they already divided by — one device pixel is the product of both, which is what [`map-plat-zoom`](../../__tests__/modules/map-plat-zoom.test.tsx) asserts rather than the figure either factor takes alone. Rounding is unchanged: the canonical paths carry one decimal at a 1000-wide frame, so a drawn coordinate lands within 0.08 px of the emitted one at 800 wide and 0.24 px at 3,840, and the canonical strings are the smaller payload above 1,000 px anyway.

Two cases keep emitting at the measured fit. A geography the buffer declines has no affine to carry. And a passed d3 instance is refit in place by `fitSize`, so by the time a transform could be derived the canonical projection and the measured one are the same object at the same scale — the basis those paths were drawn at is gone, and the two affines would compose to the identity and pin the geography at the first box it was measured in. That is `scaleCanonicalFit`'s own rule reaching a fourth derivation, and [`map-plat-resize`](../../__tests__/modules/map-plat-resize.test.tsx) holds both branches: a named projection leaves every `d` alone across a resize, a passed instance moves them.

The affine is stated once for both readers (`frameAffine`, `map-geometry/projected`): the emit applies it per coordinate, the layer applies it as a transform, and both take the same witness test. The layer's own transform is the two composed — the buffer sits at the probe scale the sixth measures the frame from, so neither affine off it is the one the layer needs, and the canonical frame reaches the measured one by their ratio.

What the fold moves is the deferral gate rather than the deferral. Every map now walks its geography once whatever it draws, because the fit is measured from that walk — so a `deferPaint` map no longer skips the pass, it skips the emit, and it keeps the ~1 MiB buffer a county atlas comes to whether or not it ever paints. That is a straight trade of memory for the bounds walk it no longer runs, and no map pays a second walk for it. [`boundary/map-path-deferral`](../../__tests__/boundary/map-path-deferral.test.tsx) counts `emitRegionPaths` for the deferral now, and counts `probeCanonicalFit` at one on both paths — a second would mean the fold had come apart and the fit was measuring its own bounds again.

The module's four outsized files split along the seams their own prose already named. `map-plat.tsx` is now its props type and the assembly alone: the geometry (`use-map-shape`), the row-to-bin join (`use-map-region-readout`), the data union both of those and the props read (`map-region/data`), the legend resolution (`map-legend/plan`), the pointer state (`map-hover-provider`), the shell (`map-frame`), and the legend's box (`map-legend-region`) each came out to stand on their own. The region layer's paint table (`map-region/paint`) and lit overlay (`map-regions-lit`) came out of `map-regions.tsx` on the same rule, and the clustering split three ways — the grouping passes, the grid they bucket into (`map-cluster/grid`), and the spherical readout (`map-cluster/geo`); the engine raise below took it to four. The shared scale-bar slider left the module for [`chart/engine/chart-legend/range-legend.tsx`](../chart/engine/chart-legend/range-legend.tsx), beside the placement resolver both colour-scaled charts already read; `map-range-legend.tsx` is the map's wrapper over it, and the slider is no longer on any barrel. `map-plat.tsx` stays the module's largest file, because roughly a quarter of it is the props doccomment that CONVENTIONS §12.1 requires.

The pure core is no longer flat. It was sixteen React-free modules interleaved with the components in one directory; it is now [`engine/`](engine), and the module root is the React shell — eighteen components, seven hooks, the contexts, and the barrel. A handful of private pure helpers still sit beside their one consumer there (`valueColumnHeader`, `bridgeRegionIdentity`, `regionDelegate`), which is what the grid and chart components do too; the engine holds every rule that more than one reader shares.

## Engine — the substrate

Every framework-free rule the map holds lives in [`engine/`](engine), a d3-shaped functional core laid out like the grid, chart, and query engines. Four leaves sit at its root — `types.ts` (the module's vocabulary, geographic `LngLat` beside frame `MapPoint2D`), `map-constants.ts`, `map-motion.ts`, and `map-geofence.ts` (the circle-to-polygon math, which is one kind and so earns no directory) — under which eleven concept directories carry the rest: `map-geometry/` (the TopoJSON decode, the ring winding, the region paths and centroids, the projected buffer they are emitted from, the mark paths and their anchors, the frame chrome, the bounding-box grid a position is located over, and the cross-instance memos), `map-projection/` (resolution, the two-stage fit, the aspect and sizing policy, the frame-to-client conversion and its inverse), `map-cluster/` (the grouping pass and the rule it settles to, the size grade, the spatial grid, the spherical readout), `map-region/` (the data union, the region identity, the categorical and the numeric scale, the layer paint table), `map-overlay/` (the ledger entry, the readout, the pick), `map-hover/` (the hover-target algebra and the `data-*` anchor readers), `map-keyboard/` (the stop list, and the cursor the keys drive across it), `map-zoom/` (the view transform, its constraint, the ceiling a prop asks for, and the gestures that move it), `map-legend/` (the plan and the entries), `map-routing/` (the polyline codec, the shared result, the failure taxonomy, the request signal and the send both clients share, the two clients), and `map-zip/` (the territory language and the matcher it compiles to, the dissolve, and the frame a territory resolves to).

Two files split by layer rather than by concept, so the engine owns its own vocabulary. `context.ts` kept the React contexts and gave up the target comparisons and the anchor readers, which need no React; `use-map-legend-registry.ts` kept the hook and gave up the `MapOverlayEntry` shape its ledger holds. The cursor, the readout, and the selection resolve against those without reaching back at the module root.

The layering invariant is grid's, verbatim — no `'use client'`, no runtime `react` / `motion` / `@dnd-kit` / `@floating-ui` imports, no runtime imports from the module root, no `index` barrel (the engine is imported file-by-file).

No reach outward stands: the engine names nothing from the module root, at runtime or in a type. The range bar's shape is the engine's own (`map-legend/plan.ts`'s `MapLegendRange`), which [`map-range-legend.tsx`](map-range-legend.tsx) takes as its props, so the arrow runs view → engine.

Two suites make the layout a gate rather than a convention. [`module-filename-boundary.test.ts`](../../__tests__/boundary/module-filename-boundary.test.ts) enforces the names — `map-*` directly under `engine/`, short kind names inside a `map-<concept>/` directory, no nesting — and [`engine-purity-boundary.test.ts`](../../__tests__/boundary/engine-purity-boundary.test.ts) enforces the four rules above for the grid, query, and map engines at once. That test replaces the greps this section used to carry, and the same paragraph in the grid and query ROADMAPs: a rule three documents asserted in prose is now asserted once in code, and it carries self-checks proving each rule can still fail.

The public surface was unchanged across the move: every barrel export keeps its name, and every function moved verbatim, so `ChoroplethChart`, the docs demo, the a11y corpus, and the benchmark suites read the same map they did before.

It moves every projected coordinate on every map, which is the module's widest blast radius, so prove it against the composite projection's insets, `staticMapGeometry`'s cross-instance cache, `scaleCanonicalFit`'s arithmetic derivation, each `aspectRatio` mode, and the deferred-centroid boundary, then re-run the four mount benches — the fit sits on the mount path. A top-grade summary on an extremum still shaves under one constant; say so in the doc rather than sizing the whole frame for it. The frame chrome is the second witness, and the World tab draws it: the globe stands outside the land's own box on every world map, so a frame holds the sides of the sphere outline or its poles and never both. Equal Earth loses its north pole line by 1.2px at 5/2, and at the land's own 2.03 it loses the outline between 16°S and 16°N instead; Mercator needs a 9/10 frame to hold its top edge, against the 1.04 the land fits at. The inset holds all of it, so the two land together — but chrome is drawn from the fit rather than placed on it, so measure the inset against the chrome memo (`cachedChromePaths`), which keys on the fitted projection.

- **A GeoJSON territory keeps its interior seams.** `zipArea` dissolves a topology exactly and cannot dissolve a feature collection at all, because a collection repeats each shared border as two independent runs of coordinates and reconciling them needs polygon clipping the module does not carry. A GeoJSON-sourced territory therefore draws as a mesh of codes rather than as one shape, with every interior border stroked — the honest reading of the input, and not the one a broker wants. `dissolved: false` reports it, so a caller can say so. Two shapes would fix it: a clipping dependency (~15 KB, and a new class of floating-point failure on shared borders that do not quite agree), or a `topojson-server` pass that builds a topology from the collection once per atlas and then merges through the exact path — the second stays in the arc index, and costs a one-off build rather than a per-territory clip. Neither is worth doing before a consumer has a ZCTA source that is GeoJSON only.

- **Coverage by county, as a measure rather than a frame.** The counties under a territory draw neutral: they are the split, and the fence carries the coverage. A broker also asks the other question — which counties do I cover, and how much of each — which the frame pass has most of the parts for and deliberately does not answer. Counting by codes centred in a county is exact against the data and needs the placement to run over every code in the atlas rather than over the covered ones, which is the pass this design was scoped to avoid; counting by land area needs the clipping above. Ship the count behind a prop, with the denominator memoised on the atlas pair the way the grid already is, and say in the readout that a count is of codes centred in a county — real code-to-county relations are many-to-many, and one centroid names one county.

- **Trim the graticule to the frame.** The pass draws the globe's lines whatever the geography frames, and the viewBox clips the rest: under `albers-usa` 202 of 2,573 projected vertices survive — 7.9% — and the whole pass costs 6.6x what a clamped one does (5.20 ms against 0.79 ms at a 1000-wide frame). `geoGraticule().extent()` takes the bound, so the shape is four `projection.invert()` calls on the viewBox corners, cached beside the chrome paths. Derive it from the frame rather than from `geoBounds(features)`, which spans nearly every longitude on a US atlas because Alaska crosses the antimeridian. It moves where the lines end, so it is a behaviour change, not a pure optimisation.

- **A ZCTA atlas in the demo.** `useMapCoverage` ships tested and undemonstrated, because the docs have no ZIP geometry to draw and the module will not invent any. The rule the other map demos hold — atlas data stays out of the package and the docs bundle, and a demo fetches it from a dev dependency as a static asset — has no ZCTA equivalent to hold it with: npm carries no ZCTA atlas package, the Census-derived national file is ~105 MB of GeoJSON across 33,092 codes, and one state is ~30 MB. Three shapes, in order of how much they ask of the repository: publish a simplified ZCTA TopoJSON as a dev dependency and follow `us-atlas`'s path exactly; commit one ZIP3's worth of real geometry as a fixture, which is small (~56 codes) and breaks the no-atlas-data rule; or fetch a remote file in the demo alone, which makes the docs build depend on a third-party host. The first is the only one that leaves the rule intact. Until then the hook's own `@example` and [`map-coverage`](../../__tests__/modules/map-coverage.test.ts) are what document the call shape.
