# Bug Audit — defects across the `ui` surface

**Date:** 2026-09-11 · **Scope:** every `.ts` and `.tsx` file under [`src`](../../src), except the test and the benchmark trees — 1,510 files and 153,159 lines. **Method:** an area sweep reads every line of a disjoint file set and reports a defect only with a concrete trigger; two adversarial verifiers then judge each claim, and a third decides a split. **Status:** 1 of 28 area segments is swept, and its verification is open; 33 segments stay open. **Living record — resolve rows in place, against the pull request that closed them.**

## Status

This audit is incomplete by design. One sweep of the whole package does not fit in one session. This container holds 4 cores, so the agent harness runs 2 sweeps at a time; a full first pass costs about 5 hours of sweep time, and the verification costs several times more. The segments below divide that cost. Each segment closes a named part of the surface, and each one costs one short session.

Segment `A01` is swept. It covers [`components/date-picker`](../../src/components/date-picker), [`components/menu`](../../src/components/menu), [`components/segment`](../../src/components/segment), and part of [`components/pdf-viewer`](../../src/components/pdf-viewer) — 49 files and 7,172 lines. It raised 15 claims, and the verification of those claims is open. A claim is not a finding until a verifier reads it and keeps it, so this document records no finding yet.

Nothing in this audit is fixed yet. Every row is a claim about the tree as of this commit, and the line numbers drift.

## Method

A unit is a disjoint file set of about 4,200 lines. One sweep agent owns each unit and reads every file in it, because a sample hides the defect that a sample misses. A segment holds one or two units.

A sweep reports a defect only when it can name the file, the line, the trigger, and the wrong result. Style, naming, and format stay out of scope, and Biome owns them. A request for a test, for a document, or for a refactor is not a defect. A repository convention is not a defect: [`CONVENTIONS.md`](../../../../CONVENTIONS.md) §3.6, §3.9, §7.2, §7.3, and §11.3 decide intent, and [`REFERENCE.md`](../../REFERENCE.md) §2 decides the tier boundary.

Two verifiers then attack every claim. The first one tests reachability: it traces the real control flow, it follows each caller and each guard, and it tries to prove the wrong behaviour cannot happen. The second one tests intent: it reads the conventions, the TSDoc, the surface docs, the open audits, and the tests, and it tries to prove the behaviour is deliberate or already known. Both verifiers refute a claim when they are not certain. A third agent decides a split, and it repeats the work instead of a vote.

A claim survives only when a concrete trigger produces a wrong result that the repository neither intends nor already records. The bar separates a wrong result from fragile code, and only the wrong result survives.

Verification runs as one batch for each unit, not as one agent for each claim. The batch costs 2 agents for each unit in place of 2 agents for each claim, and it gives each verifier the context of the neighbouring claims. This choice is what makes a segment affordable.

## Lens segments

An area sweep reads one file set, so it cannot see a defect that spans the package. A lens sweep reads across the package for one defect class. The lens segments run after the area segments, because a lens needs the confirmed list to avoid a repeat.

| Segment | Lenses | State |
|---|---|---|
| `B01` | react-hook-correctness · lifecycle-teardown · form-binding-cascade | open |
| `B02` | aria-semantics · focus-and-keyboard · error-handling | open |
| `B03` | async-races · numeric-and-geometry · date-time-locale | open |
| `B04` | unsound-types · composition-and-boundaries · browser-floor | open |
| `B05` | render-cost-and-leaks · test-soundness · build-and-config-surface | open |

Each lens hunts one class. **react-hook-correctness** reads dependency arrays against the bodies, and it hunts a stale closure, a state write in render, and a ref that the render body mutates. **lifecycle-teardown** hunts a listener, an observer, a timer, or an animation frame with no matching teardown. **form-binding-cascade** tests each bindable control against [`CONVENTIONS.md`](../../../../CONVENTIONS.md) §7.2 and §7.3. **aria-semantics** hunts a role or a state that breaks assistive technology, and an `id` reference that points at nothing. **focus-and-keyboard** hunts focus that escapes to `document.body`, a roving set with no tab stop, and arrow arithmetic that overruns. **error-handling** hunts a swallowed error and a state that stays in load forever. **async-races** hunts a state write after a newer request resolves, and a missing guard. **numeric-and-geometry** hunts a zero divisor, and `NaN` in a style or an SVG attribute. **date-time-locale** hunts a time-zone assumption and a locale-sensitive parse of a machine string; the suite pins `LANG=en-US`, so CI hides this class. **unsound-types** hunts a cast that a caller can break. **composition-and-boundaries** tests spread order against §3.9, and the barrel against §3.5. **browser-floor** tests each platform call against [`.browserslistrc`](../../../../.browserslistrc) and §11.3. **render-cost-and-leaks** hunts an unstable context value and a cache with no eviction. **test-soundness** hunts a test that cannot fail. **build-and-config-surface** reads what the area sweeps exclude: `tsup.config.ts`, `vite.docs.config.ts`, the five Vitest configs, the three `tsconfig` files, the `exports` map in `package.json`, and the three CSS files under [`src/docs`](../../src/docs).

## Not covered

The area sweeps exclude [`src/__tests__`](../../src/__tests__) — 628 files and 115,439 lines — and [`src/__benchmarks__`](../../src/__benchmarks__) — 63 files and 7,783 lines. Lens `test-soundness` in `B05` covers the test tree for one defect class only: a test that cannot fail. A full sweep of the test tree needs its own audit.

The area sweeps read `.ts` and `.tsx` only, so they exclude the build configuration, the `exports` map, and the CSS. Lens `build-and-config-surface` in `B05` closes that gap.

No sweep runs the package. Every claim comes from a read of the source, so a defect that needs a run to see — a layout result, a paint order, a real browser event sequence — stays out of reach. The browser suite and a manual pass own that ground.
