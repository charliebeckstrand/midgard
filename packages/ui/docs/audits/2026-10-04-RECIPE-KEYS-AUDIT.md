# Recipe Keys Audit — 2026-10-04

**Lens:** the names of the keys that the recipe layer exports. The kata, the kiso bundles, and the katakana bridges named a part three ways: a camelCase key (`barRail`, `headerTitle`, `rowGroup`), a nested object (`item.base`), and a flat prefix family beside the part (`bar` and `barRail`). The audit also covers bugs in the recipe engine.

**Method:** six read-only sweeps, four over the kata, one over kiso and katakana, and one review of the engine (`core/recipe/`). Each sweep read every line of its scope and found every reader of each flagged key, with aliased imports, destructuring, and text reads in tests. Each change was checked by a dump of every kata export, resolved to its class strings for each variant value (1,398 paths), before and after. The 51 `*Variants` types were checked by a forced `tsc` print of each expanded type, before and after. A temporary narrowing of `cn` and `createSlot` found no object in a class position.

**Classes:** **A** is mechanical, with no change in behavior. **B** is a small refactor that holds behavior but needs a test run. **C** needs a decision from the owner: a visual change, a public API change, or a policy change.

**Status:** each fixed row cites the pull request that closes it (CONVENTIONS §12.4).
