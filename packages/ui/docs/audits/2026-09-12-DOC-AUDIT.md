# Documentation Audit — comment accuracy against the code

**Date:** 2026-09-12 · **Baseline:** `034470d`, the commit that added the 2026-08-02 documentation audit (#1041) · **Scope:** every comment under [`src`](../../src), and the curated surface docs under [`docs/`](..). **Lens:** accuracy. A comment is a defect here when it states something the code no longer does. It is also a defect when it names a file, a symbol, or a test that no longer exists. **Living record — resolve rows in place with the pull request that closes them.**

Rows cite a symbol rather than a line, because a line number stops being true at the next edit. This audit's own first draft proved the point: it cited `map-plat.tsx:778` for a comment its own fix had already moved.

## Executive summary

The defect sat in three places. Six citations named a test, a benchmark, a component, or an audit that does not exist. Seven `{@link}` sites named five symbols that no longer exist. Nine comments across eight files in `modules/map` describe a mechanism the module has since changed. [`HOOKS.md`](../HOOKS.md) also carried three fewer type rows than the hooks barrel exports.

The map rows share one cause, and it is the shape to expect next. The hit-target rule gained a third claimant: a region layer that answers the pointer, added with `map-region/spare.ts`. The comments that enumerate the claimants stayed at two. One sibling (`map-point.tsx`) was updated and the rest were not, so the module stated the rule two ways.

Two open rows carry follow-on work, and one of them is the reason this audit closes fewer categories than it could. Nothing gates the two scanned categories, so both can rot again. The semantic category is swept in `modules/map` only.

The controlled-language regressions this sweep found belong to the August audit's lens, not this one. They were reopened in place there, and #1148 closed that audit. Rule 10 stands at zero, and [`controlled-language-boundary.test.ts`](../../src/__tests__/boundary/controlled-language-boundary.test.ts) now holds rules 4 and 6 to a per-file ledger; [`STE.md`](../../../../STE.md) carries the scope decisions that audit was holding.

## Method

Five scans ran over `src`, and one subsystem had a per-file read. Each result was checked by hand before it became a row. A clean result is worth as much here as a defect, so the Ruled out section keeps the negative results for the next audit.

The link scan collected every `{@link}` target from a comment and resolved it against the declarations in the package. Read its history as a warning, because its first pass nearly buried five real defects. That pass reported 51 unresolved targets, and a sample of twelve came back false. That sample nearly cost the list. The package places doccomments in three legal spots, which `tsdoc-coverage-boundary.test.ts` enumerates. A scan that reads only `function` / `const` / `type` declarations sees none of them.

The map read found one of those five independently, which is what sent the scan back for a second pass. Once it also read destructuring, object members, and imports, the list fell from 51 to 7, and 5 of the 7 were real. Sample a scan's false positives to fix the scan, never to dismiss its output.

The citation scan extracted every `*.test.ts(x)` and `*.bench.ts(x)` filename named inside a comment, then tested each for existence. This found four of the six closed citation rows. It is the cheapest high-yield scan in this audit, and it is the one to run first next time. Hand the tree roots in directly: [`walk-source.ts`](../../src/__tests__/helpers/walk-source.ts) prunes `__tests__` and `__benchmarks__` by default, and three of the four defects lived inside those trees.

The default-value scan compared each `@defaultValue` claim against the destructuring defaults in the same directory. The modal-verb scan repeated the August audit's language scan at that audit's own scope. The index scan duplicated work that [`surface-index.test.ts`](../../src/__tests__/docs/surface-index.test.ts) already does on every run. The one thing worth recording is why that test missed the gap it found; see the index row below.

No scan reads whether a comment still describes what its code does, so `modules/map` had a per-file read instead. It is the highest-churn subsystem, at 73 files changed since the baseline. It returned nine comments against about 90 minutes of read. That rate is the number to plan the remaining subsystems against.

## Open

**Both scanned categories have a gate now, and this entry's prediction had already come true.** ✅ RESOLVED (#1167) — [`comment-reference-boundary.test.ts`](../../src/__tests__/boundary/comment-reference-boundary.test.ts) holds the two cases: every test or benchmark file a comment names exists, and every `{@link}` target names a symbol the package or the TypeScript library declares.

The rot arrived inside a month. Steps 7 and 9 of the [2026-09-11 audit](2026-09-11-TEST-ARCHITECTURE.md) moved eight boundary rules into `biome.json` and `biome-plugins/`, and deleted the tests that had held them. Nine comments across seven files still named the deleted files, and no run said so. Each cites the rule's current home now. The contracts never moved; only their pins did, which is the shape to expect whenever a rule changes instrument.

**The link scan does not take the placement proposed above, because the premise does not survive a measurement.** A program over every barrel does not remove the false-positive class by construction; it creates one. `getSymbolAtLocation` resolves a target against the scope of the file that names it, and a `{@link}` target is almost never imported there — [`core/aria-attr.ts`](../../src/core/aria-attr.ts) links `dataAttr`, which its sibling exports. Measured against that program, 1,255 of 3,759 sites read as unresolved. The program is also blind to every file no barrel reaches, and `__benchmarks__/fixtures.ts` held one of the five link defects this audit found by hand.

What works is the instrument the Method section's own second pass converged on: membership against every name the package declares, plus the standard library globals. That is a source walk rather than a program, so both scans share one, and the walk must carry its own collector — [`walk-source.ts`](../../src/__tests__/helpers/walk-source.ts) prunes `__tests__` and `__benchmarks__` at every depth, and the docs engine keeps a second pair of those trees under `docs/engine/`. A walk blind to them reports a file that exists as a dangling citation. On the tree today the link case reads 2,517 sites and no unresolved target, so it lands green; the citation case landed red on the nine defects above.

Membership is the weaker test, and the gate states its own limit. It catches a target naming a symbol nothing declares, which is the whole class both scans found. It cannot catch a target naming the wrong symbol of several, which nothing in the tree answers today.

**A stricter instrument already ships, and adopting it is the next row rather than this one.** ✅ RESOLVED (#1195) — the gate keeps membership. The resolver's index decides nothing a reader sees, so neither a gate on it, a wider resolver, nor 652 rewritten targets buys a rendered change.

The row's premise does not hold. Since #1148, [`doc-inline.tsx`](../../src/docs/engine/components/api-reference/doc-inline.tsx) and [`doc-description.tsx`](../../src/docs/engine/components/api-reference/doc-description.tsx) render every symbol target as plain text, resolved or not. No client component reads the `links` map the resolver fills. The extractor reads only its keys, to track the source file of each target for cache invalidation. The `DocLink` doccomment still promised a hover card, and the gate's own header repeated the claim. Both now state what the renderer does.

The original text of this row follows. [`link-resolver.ts`](../../src/docs/engine/api-reference/engine/link-resolver.ts) builds the index the renderer itself resolves a `{@link}` against, and it holds PascalCase top-level declarations outside `docs/` — `isPascalCase` is `/^[A-Z]/`. Membership here accepts any of the 13,670 names the package declares anywhere, locals and parameters included. The gap is measured: 652 of the tree's 2,515 targets have a lowercase head, `{@link dataAttr}` in [`core/aria-attr.ts`](../../src/core/aria-attr.ts) among them, so they pass this gate and render as plain text. That is a real defect class this gate does not see, and gating on `createLinkIndex` starts red on all 652, so it is its own change with its own remediation. The failure message claims only what membership measures until then.

Two scoping decisions are worth recording. The citation case reads comment trivia rather than whole file text, which the Method section already specified: the docs engine's api-extractor suite asserts on the path of a test file that is not supposed to exist, and a whole-text scan reads that argument as a defect. It also reads Markdown under `src`, because five of the nine live defects sat in a README rather than in a comment.

The gate costs about 3s against `tsdoc-coverage`'s 2.1s, inside the project's 30s `testTimeout`. Two guards carry that, and each is sound by construction rather than by sampling. A comment's text is a substring of its file's text, so a file whose text holds neither `.test.ts` nor `.bench.ts` cannot hold a citation, which excuses 2,183 of 2,256 source files from the comment read. And `ts.getJSDocCommentsAndTags` walks parent pointers, so the lookup and the cost of building them are gated together on the file holding `{@link` at all, which two thirds of the tree does not. The link half is what remains, at about 2.9s, because the `declared` set still needs every file parsed.

The comment read is [`extractComments`](../../src/__tests__/helpers/controlled-language.ts), the reader this package already had, not a `ts.createScanner` pass. A raw scanner carries no parser context: one template literal holding a substitution desynchronizes it, and it then swallows every comment up to the next backtick. A `` `${number}/${number}` `` *type* is enough, and [`chart-layout.ts`](../../src/modules/chart/engine/chart-layout.ts) loses 118 of its 120 comments to exactly that. Across the tree the scanner saw 20,304 comments against the reader's 25,007, so the first draft of this gate was blind to 19 percent of the surface it claims. A citation staged below that template literal proves the difference: the reader reports it, the scanner never saw it.

**The gate stops at `src`, so this audit's second scanned surface stays ungated.** `docs/` is deliberately out. An audit records a dangling citation by quoting it — the Closed table above names three files that do not exist, which is the point of the row — and a plan names the test file it proposes to add. Nine such references sit under `docs/audits` and `docs/plans` today and every one is intended, so a gate there would report authored prose as drift. The curated surface docs carry no citation at all, and [`surface-index.test.ts`](../../src/__tests__/docs/surface-index.test.ts) already holds their export rows. What stays unguarded is therefore narrow: a future curated doc that starts citing a test file.

**`TouchTarget` has no browser pin for the claim its doccomment makes.** ✅ RESOLVED (#1197) — [`touch-target-geometry.test.tsx`](../../src/__tests__/browser/touch-target-geometry.test.tsx) measures the activation region in Chromium. On a fine pointer, a 16px host keeps its own box, and the span floors the hit area at 24px, centred on the host. A point outside the host and inside the floor activates the host; a point past the floor does not. A host at or above the floor collapses the span onto its own box. On a coarse pointer the floor is 44px. `Emulation.setTouchEmulationEnabled` makes `pointer: coarse` match; `Emulation.setEmulatedMedia` ignores the `pointer` feature, so it cannot stand in. The doccomment cites the pin now.

The original text of this row follows. The comment says the floor holds the activation region rather than the visible bounds. [`touch-target.test.tsx`](../../src/__tests__/primitives/touch-target.test.tsx) asserts the floor classes under jsdom, which is the right environment for a class assertion ([§10.5](../../../../CONVENTIONS.md)). No test measures the geometry those classes resolve to. `grid-target-size.test.tsx` is not that pin: it covers the grid's own `::before` expansion, a different mechanism. The correction made the citation resolve, which also made the gap quieter. The doccomment now states the gap in the file where a reader stands when it matters.

## Ruled out

**Every `{@link}` target resolves, now that the five above are fixed.** Two sites still read as unresolved and are not. [`link-syntax.ts`](../../src/docs/engine/api-reference/link-syntax.ts) and [`extract-doc.ts`](../../src/docs/engine/api-reference/engine/extract-doc.ts) document the `{@link …}` grammar itself, so their targets are the placeholder and the delimiter.

**The `@defaultValue` claims are accurate.** All 529 of them. One scan hit needed a hand check and did not survive it: `ChartReferenceLine.dashed` documents `@defaultValue true`, and the code reads `line.dashed !== false`. The claim is right; the scan had matched an unrelated default in a sibling file.

**The package carries no marker debt.** No `TODO`, no `FIXME`, no `HACK`, no `XXX` outside a string, and no `@deprecated`. Staleness here is silent prose, never a flagged marker, so a marker sweep finds nothing.

**The `vector-effect` prose in `modules/map` is correct.** Three comments discuss `vector-effect="non-scaling-stroke"` after the module took over its own stroke scaling. Each explains why the module does *not* use it. That is historically aware prose, not drift.

**The component, module, and primitive indexes are not stale.** [`surface-index.test.ts`](../../src/__tests__/docs/surface-index.test.ts) checks those three per directory, matching the granularity [§12.2](../../../../CONVENTIONS.md) sets, and the August audit walked the same ground. A symbol-level scan reports false gaps against them.
