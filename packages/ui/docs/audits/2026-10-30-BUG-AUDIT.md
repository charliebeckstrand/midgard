### B01-C01

- Claim (sweep): The column narrows to its affordance icons plus a small text allowance, and its multi-word header title truncates, although the auto-size action is documented to give the width that shows the header without truncation.
- Trigger (sweep): A resizable grid with no rendered body rows (an empty result or a loading skeleton) and a data column whose title is more than one word; the user picks "Auto-size this column" or "Auto-size all columns", or presses Enter / double-clicks the resize handle.
- Contract (sweep): sizer.ts contentWidth TSDoc: "The content width (px) of a column. That is the smallest width that shows its header and every measured body cell without truncation. Every sizing path reads it from this one function."

- **id**: B01-C01
- **verdict**: CONFIRMED
- **mechanism**:
  - `engine/grid-sizing/measure.ts:543` `if (scan.has(id) && cellsOfColumn) scans.set(id, scanBodyCells(cellsOfColumn))`. A column with no body `td` gets no scan.
  - `engine/grid-sizing/measure.ts:561-562` `for (const [id, { widest: width, least }] of scans) { widest.set(id, Math.max(width, titles.get(id) ?? 0))`. The header title width enters `bodies` only through a scan, so a column with no body cell has no entry and its title width is lost.
  - `engine/grid-sizing/sizer.ts:295-302` `for (const id of ids) widest.delete(id)` / `read(env, ids)` / `contentWidth(col, getFloor(col), widest.get(String(col.id)) ?? 0, false)`. With no entry, `body` is 0.
  - `engine/grid-sizing/sizer.ts:147` `return Math.max(floor, Math.min(body, cap))`. The result is the floor.
  - `engine/grid-sizing/measure.ts:360-364` `const headerFloor = isSingleWordTitle(col.title) ? header : Math.max(0, header - titleIntrinsic) + HEADER_TRUNCATE_ALLOWANCE` / `return { floor: clamp(headerFloor, col.minWidth ?? DEFAULT_MIN_COLUMN_SIZE, max), header }`. For a multi-word title the floor is the affordances plus 24px (`engine/grid-constants.ts:97` `export const HEADER_TRUNCATE_ALLOWANCE = 24`).
  - `engine/grid-sizing/sizer.ts:375-384` `sizeColumn` calls `takeControl(env.columns)` and returns `freshContent(env, [col])` with `persist: 'widths'`. The column is held at that width in `manual` mode.
  - Empty body markup: `grid-body.tsx:499` `if (rows.length === 0) return <TableEmpty ...>` and `packages/ui/src/components/table/table-empty.tsx:48` `<TableCell colSpan={columns} ...>` (no `data-grid-col`). Loading: `grid-body.tsx:449` `if (loading) return <GridLoadingBody .../>`, and `grid-skeleton-cells.tsx:40` "A placeholder carries no `data-grid-col`".
- **trigger**: Verified, with one part refuted (see the ruled-out list). A client grid (resizable by default) whose filter or search empties the view, or a grid that shows its loading skeleton over rows it still holds, with a data column whose title is not one word. The user presses Enter or double-clicks the separator of that column, or picks "Auto-size this column" / "Auto-size all columns". The header stays live in that state: `grid-data-resolvers.ts:488` `return { hasRows, hasData: hasRows || (narrowed && !args.showingError) }` (client side, `rows` holds the source, so `hasRows` is true), `grid-data.tsx:679` `interactive: hasData`, `grid-column-header.tsx:212` `const canResize = resizeActions !== null && interactive`.
- **intent**:
  - `engine/grid-sizing/sizer.ts:126-129` "The content width (px) of a column. That is the smallest width that shows its header and every measured body cell without truncation. Every sizing path reads it from this one function."
  - `engine/grid-sizing/measure.ts:338-340` "`header` is the width (px) that the header needs to show its title in full. The automatic table layout gives a column at least this width, so the content width of a column includes it (see `contentWidth`)."
  - Against: `engine/grid-sizing/measure.ts:459-461` "The widest cell (px, border box) of each scanned column: a body cell, or the header with its title in full ... A scanned column that rendered no body cell has no entry." This sentence states the measurement fact. It does not say that an auto-size action may truncate the header, and the two sentences above it say that the content width includes the header. No test covers an auto-size over an empty body (`packages/ui/src/__tests__/modules/grid-column-sizer.test.ts` names: no empty-body case).
- **reach**: shipped. `packages/ui/src/docs/pages/modules/grid/filters/date-number-and-boolean-filters.tsx:68` `return <Grid columns={ticketColumns} rows={tickets} getKey={(row) => row.id} />`, with `:49` `title: 'Estimate (hours)'` and `filterType: 'number'`. Terms: `<Grid`, `title: '<word> <word>`, `search`, `filterable`.
- **severity**: medium. A shipped surface shows a wrong result in normal use (the auto-size action truncates the header that it must show in full, and the column stays held narrow after the rows come back), and the user can recover with a drag or "Reset column widths".

- **Q2** (B05 Q3; gates the C05 half of S3). How does the slot learn that a drag holds the press?
  - Axis A: add `press` (or a `held()` reader) to `GridNewRowSession`. The slot keeps its own seat logic.
  - Axis B: give the session a guarded seat built in the cursor in place of the raw `moveTo`. The guard lives in one place with the data-cell `seat`, and the session type changes.

  - Axis A: they leave the count only. A total wider than its cells still widens the column in the fixed layout.
  - Axis B: they leave both. The fixed-layout content width then ignores a wide total, and `scanBodyCells` must skip them too.

  - Border box: the automatic-layout styles and `least` change.
  - Content: the engine bounds and `contentWidth` add the cell chrome, and the drag clamp changes.
- **Q5** (B05 Q1; gates S13). What does an unseated movement key do on a one-stop first row?
  - Axis A: seat on the header and stop. This changes the documented seed-then-step behavior for grouped grids only.
  - Axis B: seed-then-step as on a flat grid. This keeps the documented behavior, but the toggle must come with a seat so that the reader sees the header that changed.
- **Q6** (B05 Q2; gates S14). Which handlers earn the static Tab stop?
  - Axis A: `onRowClick || onRowDoubleClick` only, the handlers that `rowShellProps` fires on Enter.
  - Axis B: any clickable handler (`isRowClickable`). This also covers the cell-only lead (L15), but the row shell must then fire the cell handler, which widens S14 into `engine/grid-row/shell.ts`.
- **Q7** (B03 Q1; gates S15). When a hidden set names a `hideable: false` column, which one wins?
  - Flag wins: the engine drops the id from `columnVisibility`, as for frozen and non-data columns, and the manager renders the row checked and disabled. The grid then ignores part of a controlled `hidden` value.
  - Set wins: the grid keeps the column hidden, and the manager enables the checkbox while the column is hidden. The manager then needs a state that is neither "checked and disabled" nor "free".
  - Either outcome decides whether `grid-group-manager.tsx` joins S15.
