### B01-C01 — an inline `onReset` breaks the identity of `actions`

- **File:** `packages/ui/src/components/form/use-form-reducer.ts`
- **Mechanism:** `reset` lists the prop, so each new `onReset` makes a new `reset`, a new `actions`, and a new context value. `use-form-reducer.ts:258` `onReset?.()`; `:260` `[onReset],`; `:395` `[getValue, setValue, setErrorsExternal, setTouched, reset],`; `form.tsx:109` `onReset,`; `context.tsx:95` `<FormActionsContext value={actions}>`. - **Trigger:** `<Form onReset={() => …}>` under a parent that re-renders.
- **Documented intent:** `context.tsx:18` "Imperative form mutators. Stable across renders, so reading them never forces a re-render."; `context.tsx:53-54` "The actions object is referentially stable, so subscribing to it never triggers a re-render"; `use-form-value.ts:44` "`setValue` and `setTouched` keep their identity across renders."; `CONVENTIONS.md:182` "Use `useStableEvent` also for each other handler that keeps one identity for the mount and calls the newest props." - **Reach:** none. No root passes `onReset` to a Form; the only site is `form.test.tsx:102`, with a stable `vi.fn()`.
- **Severity:** low. Extra renders and identity churn, no wrong state, and no root passes the prop.
- **Prior art:** none. `2026-08-08-EFFECT-EVENT-PLAN.md:64` moved "`use-form-reducer.ts`'s two callback refs" (`reportSettled`, `reportInvalid`); `onReset` was never a ref. CLEANUP C8 records the compiler `Todo` skip, so no compiler memo hides the churn.
