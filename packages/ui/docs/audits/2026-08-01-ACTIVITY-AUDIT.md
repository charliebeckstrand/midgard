# React `<Activity>` Adoption Audit — Open Findings

Survey of `packages/ui` (2026-08-01) for surfaces where React 19.2's `<Activity>` would retire hand-rolled hide-or-unmount machinery. Method: a sweep of every conditional-render site, every `aria-hidden`/`inert` pair, and every module-level cache whose stated reason is a remount, each finding read back against live source. Line numbers are as of this commit and will drift.

A naming note, since the request named it `<Visibility>`: React 19.2 exports `Activity`, not `Visibility` — verified against the installed runtime (`react@19.2.7`) and `@types/react@19.2.15` (`ActivityProps`, `mode?: 'hidden' | 'visible'`). `Visibility` was a candidate name during the `Offscreen` → `Activity` rename and never shipped.

Semantics assumed throughout, verified locally rather than from the docs: `mode="hidden"` keeps children in the DOM at `display: none`, preserves their DOM and React state, tears down their effects (cleanup runs on hide, setup re-runs on show), and renders updates at a lower priority off the visible path. The package's own tests pin all three — [`__tests__/primitives/current.test.tsx:196-246`](../../src/__tests__/primitives/current.test.tsx) for state and effect lifecycle, [`__tests__/browser/current-rest.test.tsx:29-51`](../../src/__tests__/browser/current-rest.test.tsx) for `display: none` in a real browser.

Landed context, treated as the house idiom rather than as findings: [`primitives/current`](../../src/primitives/current) holds inactive panels through its `mount` policy (`current-content.tsx:181-231`), and [`primitives/ready-reveal`](../../src/primitives/ready-reveal) rests its placeholder once the reveal settles (`ready-reveal.tsx:115-139`). Both pair Activity with a rest latch — `useRestHold` (`current-content.tsx:61-79`) — because `display: none` cannot animate, so the hold applies only after the transition lands. Every finding below inherits that shape; none of them can wrap Activity around an animating subtree directly. Only Tabs and Nav consume the primitive today (`tab-contents.tsx:50,76`, `nav-content.tsx:11,16`), which is why the same problem recurs uncovered in five more compounds.

## High

- [ ] **`src/modules/grid/grid-group-leaf-row.tsx:278,286-290`** (with `grid-detail-row.tsx:97-98`, `grid-total-row.tsx:211`) — a grouped body stands down virtualization by design (`grid-body.tsx:357-384`), so every leaf of every group is mounted and re-rendered on every body render whatever its group's expansion; a collapsed leaf is taken out of reach by a hand-rolled triad — `aria-hidden`, `inert`, and a `tabIndex` expression — with roving gated separately on `expanded` at `:278`. `<Activity mode="hidden">` supplies all three effects from one prop and adds the one no attribute can: the collapsed leaves stop rendering on the visible path. This is the package's largest concentration of live-but-unreachable DOM, and the only finding here with a perf claim worth measuring. **Fix:** rest the leaf, detail, and total rows into a hidden Activity once the `1fr`↔`0fr` reveal lands (`recipes/kata/grid.ts:500-507,546-552`), reusing `useRestHold`'s shape; keep `aria-hidden`/`inert` for the in-flight collapse only, and bench a wide grouped grid against the current shape before adopting.

- [ ] **`src/components/stepper/stepper-panel.tsx:25`** — `if (value !== currentValue) return null` discards the outgoing step wholesale, so stepping back through a wizard loses every uncontrolled input, scroll offset, and effect-held value in the panel just left. This is the canonical Activity case, and Tabs already solved it in this package: `StepperPanels`/`StepperPanel` carry the same current-value shape as `CurrentContents`/`CurrentContent` but reimplement the bare unmount instead of extending the primitive ([`CLAUDE.md`](../../../../CLAUDE.md) §1.1). **Fix:** back the pair with `primitives/current` as `tab-contents.tsx:50,76` do; the Activity hold, the mount policy, the fade choreography, and the rest latch all arrive with it, and `StepperPanel` shrinks to its `useA11yDisclosure` wiring.

## Medium

- [ ] **`src/components/collapse/collapse-panel.tsx:26,37-48`** (with `accordion/accordion-panel.tsx:31-43`) — both unmount while closed and have no way not to; the `AnimatePresence` wrapper exists solely to defer that unmount past the height animation. Neither offers the `mount` policy Tabs has, so any consumer whose panel holds state — a form, a scrolled list, a resolved query — pays a reset on every collapse. **Fix:** give both a `mount` prop resolving through `primitives/current`, defaulting to today's `active` so existing behavior is unchanged; `always`/`lazy` then rest the closed panel in a hidden Activity once the height transition completes.

- [ ] **`src/docs/engine/components/example.tsx:87-99`** (with `:163-177`) — because `Collapse` unmounts, `Example` carries two workarounds: a `derivedRef` that caches the derived source so it stays visible through the close animation, and a mount-time `hasDerivedCode` latch that settles panel existence once to avoid re-walking the subtree. The `CodeBlock` inside re-tokenizes on every reopen, softened only by the module LRU at `code-block.tsx:9-23`. A `Collapse` with a `mount` policy holds the panel in a hidden Activity: the walk runs once, the tokens survive, and both workarounds go. Chains with the open finding on the same probe in [`2026-07-13-DOCS-PERF-AUDIT.md`](2026-07-13-DOCS-PERF-AUDIT.md) (cited there as `example.tsx:78`; now `:87`). **Fix:** land the `Collapse` `mount` prop above, then set `mount="lazy"` here and delete `derivedRef` and the `hasDerivedCode` latch.

- [ ] **`src/components/json-tree/json-tree-node.tsx:160-171`** (with `:90`, and `tree/tree-item-children.tsx:49-63`) — a collapsed subtree unmounts, so an uncontrolled node's local `userOpen` state is lost with it: collapsing a branch and reopening it resets every descendant's expansion. The controlled path (`onExpandedChange` over a path set) survives; the uncontrolled one does not, which reads as a defect rather than a policy. **Fix:** hold opened subtrees in a hidden Activity on the `lazy` shape only — hold what has been opened, never pre-mount what has not. `always` is wrong here: hidden Activity still renders its children once, so a recursive tree over a large payload would mount the whole document up front.

- [ ] **`src/components/pdf-viewer/pdf-viewer-thumbnails.tsx:72-74`** — the desktop sidebar stays mounted and is hidden by three separate mechanisms — `aria-hidden`, `inert`, and a `k.sidebar.closed` class — while the whole thumbnail list keeps rendering behind it. Unlike the grid rows this one has no reveal animation to wait on, so it is the cleanest single-site substitution in the package. **Fix:** wrap the `<aside>` body in `<Activity mode={sidebarOpen ? 'visible' : 'hidden'}>` and drop the `aria-hidden`/`inert` pair; keep the class for the width transition.

- [ ] **`src/components/tabs/tabs.tsx:60-79`** (with `tab-contents.tsx:42-48`) — a context-published ref-count exists only so an inactive tab can keep its `aria-controls` under `mount="always"`, where its panel is guaranteed in the DOM. That is a counter, a registration callback, an effect, and two context fields to answer "is my panel mounted?". Collapse, Accordion, and Stepper each need the identical answer the moment they adopt a mount policy, so the abstraction boundary is in `primitives/current`, not in Tabs ([`CLAUDE.md`](../../../../CLAUDE.md) §1.1). **Fix:** hoist the registration into `primitives/current` and expose it as a hook before the next consumer copies it; do this ahead of the Stepper and Collapse work, not after.

## Low

- [ ] **`src/components/tabs/tab.tsx:137-146`** (with `:41,88`) — the latched `onPreload` fires on first hover or focus of an inactive tab so a caller can warm the panel. Under `mount="lazy"`/`"always"` the panel is already mounted and its hidden Activity pre-renders it, which warms render-phase work for free — a `lazy()` chunk, a `use()`d promise. It does not warm effect-driven work: hidden Activity mounts no effects, so a React Query `useQuery` inside a held panel still does not fetch until the panel is shown. The hook stays; the documentation is what is wrong, since nothing states which half the mount policy already covers. **Fix:** note the split in `onPreload`'s TSDoc and in the `mount` remarks on `tab-contents.tsx:23-32`.

- [ ] **`src/components/code/code-block.tsx:9-23,80-113`** and **`src/modules/map/map-geometry-cache.ts:9,124`** — both module-level caches name a remount as their reason, the map one explicitly citing "a tab switch under `mount="active"`". An Activity hold removes that remount, but neither cache goes away: both also serve cross-instance sharing (two plats on one atlas, the same snippet in two places), which Activity does not address. Recorded so the next reader does not mistake them for Activity candidates. **Fix:** none; revisit only if a hit-rate measurement shows the remount case dominating.

- [ ] **`src/primitives/current/index.ts:7`** — `useCurrentPanelActive` is exported with no in-package consumer. It covers the window a held panel is live but out of view — mid-crossfade, where the Activity hold is released — so it becomes load-bearing for consumers the moment Collapse and Stepper adopt the policy. **Fix:** carry a usage example into [`PRIMITIVES.md`](../PRIMITIVES.md) alongside the Stepper work.

## Ruled out

The negative results, so the same ground is not re-covered.

Floating surfaces — Tooltip, Popover, Menu, Select, Combobox, Listbox — all mount through `primitives/portal/presence-portal.tsx:47-67` and should keep unmounting. This is measured, not assumed: `__benchmarks__/browser/tooltip-lifecycle.bench.tsx:17-23` puts the whole surface subtree at ~1.15ms to rebuild, reclaimable only on a full cycle the exit fade does not already absorb, against a resident portal node per surface. Their options are derived from props, so there is no state a hold would preserve.

Dialog, Drawer, and Sheet run the same lifecycle through `primitives/overlay/overlay.tsx`, with scroll lock, focus trap, and floating-ui's `markOthers` all keyed to `open`; a resident modal would need every one of them gated by hand — more custom code, not less.

The chart legend's `inert` (`modules/chart/engine/chart-legend/legend.tsx:839`) marks a *visible* non-interactive legend, not a hidden one, and the measuring ghost at `:873-894` must lay out to be measured. `recipes/kata/toggle-icon-button.ts:11` cross-fades two stateless icon leaves. `components/sidebar/sidebar.tsx:62` mini mode is a CSS collapse that never unmounts. None have state or effects to preserve.

`modules/chart/engine/chart-context-menu.tsx:64-68` mounts a genuinely second copy of the chart in the fullscreen dialog, re-measured at the dialog's size. Activity preserves a subtree where it stands; it cannot relocate one, so the re-mount is inherent.

## Sequencing

The findings are one abstraction, not seven adoptions: hoist the mounted-panel bookkeeping into `primitives/current` first, then Stepper (the clearest reuse), then Collapse and Accordion — which drops the docs `Example` workarounds as a consequence — then the PDF sidebar as an isolated substitution. Grid rows land last: it is the only finding claiming a performance win, and it needs a grouped-body benchmark beside `tooltip-lifecycle.bench.tsx` before and after, since nothing in this audit is measured yet.

Two constraints apply to every one of them. `display: none` cannot animate, so each hold rests behind its existing transition rather than replacing it. And hidden Activity renders its children once, so `always` is only safe over bounded content — the recursive trees take `lazy` or nothing.
