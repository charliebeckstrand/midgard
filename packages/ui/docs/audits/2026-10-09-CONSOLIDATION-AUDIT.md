# Consolidation Audit — 2026-10-09

**Lens:** code that two or more sites write out by hand, where one source of truth (a hook, a helper, a component, a primitive, a recipe, a type, or a constant) can hold it. A **bypass** is a site that hand-writes a shared piece that exists. A **twin** is logic written at two or more sites with no shared piece yet.

**Scope:** `packages/ui/src` first, outside the tests and the benches. Then the places where `apps/*`, `packages/shared`, `packages/auth`, and the docs app (`packages/ui/src/docs`) rewrite a piece that `ui` or `shared` holds or should hold.

**Method:** six read-only sweeps, one for each scope: the shared layer (hooks, utilities, core, primitives, providers, layouts, structure, recipes); components A to L; components L to Z; the Grid, Query, and Dashboard modules; the Chart, Map, and Chat modules; and the apps, `shared`, `auth`, and the docs app. Each sweep read every site it cites. The load-bearing claims were then read again by hand (marked **checked**). No claim is *probed*: no scratch test ran. A row that says "needs a test" names the case a test must hold before the change lands.

**Not raised again:** the 2026-09-27 redundancy audit (closed), the 2026-10-07 surface tightening audit (closed, including its declined items U11, the panel shells, and the other "checked, not worth it" pairs), the 2026-10-06 structure audit (S3 has no new evidence), and every row of `2026-10-09-EFFECT-AUDIT.md`. Where a row here touches a file that an open effect-audit row also edits, the row says so.

**Classes:** **A** is mechanical, with no change in behavior. **B** keeps the documented behavior, but a drifted site changes (often a bug fix), or a test must hold an edge case. **C** needs a decision from the owner: a new or changed public export, a change across packages, or a visible change (CLAUDE.md §1.1, §3.1).

**Start:** *Yes* marks a row of high confidence with one rule. Section 6 groups the *Yes* rows into pull requests.

**Status:** *Fixed in #NNNN* where a pull request closes the row. *Open* where no pull request closes the row yet. *Declined* where the owner chose to leave a row as it is (CONVENTIONS §12.4).

- Scroll ancestor walks in `scroll-area-utilities.ts`, `virtual-options.tsx`, and `use-scroll-within.ts`: the meanings differ on purpose (overflow required or declared, the stop at a clip, the axes).
- Raw ResizeObservers that skip `useResizeObserver`: each is a pre-paint layout effect, gated on a flag, or keyed on more than a ref. The effect audit keeps them.

- The List and QueryBuilder `Reorder` wrappers: about 8 lines. List loads `Reorder` lazily and QueryBuilder eagerly, which is a bundle question, not consolidation.
- Grid static sortable bindings, the row and column reorder adapters, the rule-token markup, the `Reorder.Item` drag state, the zone wrappers, the tile focus hand-off, the modifier gates, and the announcement builders: 2 to 10 lines each, or wording per module.

- The Mimir server clients, `getSignInProviders` and `getTurnstileSiteKey`, query hooks seeded with `initialData`, `staleTime` in each provider, the register and login page wrappers, the proxies, the passkey ceremony, and the two app header bars: Next or TanStack glue, or 5 to 10 lines with different error rules.
