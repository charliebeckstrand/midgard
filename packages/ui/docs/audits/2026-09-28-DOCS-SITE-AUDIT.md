# Docs Site Audit — 2026-09-28

**Lens:** correctness of the `ui` docs site under `packages/ui/src/docs`: the engine (runtime chrome, Vite plugins, `derive-code`, the API-reference extractor) and the demos. Design and idiom come second: where a speed pass left code harder to reason about, and where a demo teaches the wrong use of `ui`. Demo code is also documentation, because `derive-code` turns it into the "Show code" snippet that a reader copies.

**Method:** six read-only sweeps over the 212 files (about 25,000 lines): the engine runtime and chrome, the build plugins and `derive-code`, the API-reference extractor, and three slices of the demos. Each row carries its check. **P** is a probe: a temporary Vitest case (removed after), a `buildApi` manifest dump and diff, a real Vite 8 dev server or build, axe, or `tsx`. **R** is a close read of the code and its callers. **L** is a lead that no probe reproduced. `tsc -p tsconfig.docs.json` passes. Every demo renders in jsdom with no console error or warning, so none of the rows below shows up as a crash.

**Severity:** **high** means a reader sees wrong output on a common path, or the site fails to recover. **medium** means a defect on one path, or a snippet or idiom that teaches wrong use. **low** means drift, dead code, or a small a11y gap.

**Status:** *Open*, *In review* (a pull request is open), or *Resolved* (merged). Resolve each row against the pull request that closes it (CONVENTIONS §12.4).

## Summary

The site works, and the defects cluster behind a few causes. Most of the demo rows are symptoms of the first two.

1. **Snippet derivation emits invalid or misleading code** (§3). A helper component under a recognized element prints its whole source inside the JSX, repeated per use (C1). The demos of at least ten pages hit it. Fact matching drops the props of repeated tags, and an authored `={false}` or an element prop with children is lost (C2, C4, C5). No gate parses a derived snippet, so none of this fails a test.
2. **Hand-written `code` overrides drift.** They are untyped strings. The Grid "Search highlight" override passes `filter: false`, which `GridSearch` does not have (D15). Others omit required props or close no tag.
3. **The API reference drops and mistypes props** (§4). A type declared outside the component's file gets no reference card (A1: Grid, the charts, Card, Stack). Intersections print as unions (A2: every `color` ends in `| string`). Factory-built components show empty tables (A3: 57 descriptions and 24 tables lost).
4. **A failed demo chunk loops forever** (E1). The registry evicts a rejected import inside its own handler, so React re-imports on each retry and the error card never renders.
5. **Every demo or component edit reloads the dev page** (B1). The virtual modules invalidate without comparing their output.

Two gates are missing across the whole site: no test renders the demos, and no test covers `registry.ts`, `host.tsx`, `use-hash.ts`, or `app.tsx` (§7).

## 6. Design proposals

In order of value per cost. P1 turns most of §3 and §5.2 into failing tests before any fix, so it goes first.

**P1. A snippet gate.** A corpus test that renders each demo through the real `docs:pre` transform, derives every Example's snippet, and parses it as TSX (`ts.createSourceFile` parse diagnostics). It fails on a syntax error, a duplicate top-level declaration, or a JSX tag with no import or declaration. Run the same parse over every `code` override. Two sweeps ran this shape as a probe, so it is feasible. It lands with an allowlist of today's failures, and each §3 fix shrinks the list. It replaces nothing; today no test ever reads a derived string (`demo-code-block.test.ts` checks only that one exists). *Landed in [#1612](https://github.com/charliebeckstrand/midgard/pull/1612) with 27 known failures. It also keeps `src/docs` out of the compiled test run, which put the compiler before `docs:pre`.*

**P2. One declaration table for helpers and facts.** The build emits per file an array of `{ names, code }` blocks, JSX helpers included, plus each helper's name and dependency indices. The runtime resolves helper elements and fact texts into one name-keyed hoist set, printed in source order. This replaces the joined `__code` string, the `isJsxHelperStatement` exclusion, and the verbatim `snippet` case. It closes C1, C3, and B6, and with AST-based identifier resolution, C8. It pairs with one authoring rule for the README: a stateful or mapped Example is `<Example><ChildlessHelper /></Example>`. A helper never returns `<Example>` itself, and a helper never nests inside a recognized element. Cost: medium; the facts, collect-helpers, and snippet tests change.

**P3. Retire `code` overrides where derivation is right.** After P2, most overrides in `grid/index.tsx`, `editable.tsx`, and the component demos restate what the walker prints. Each one is an untyped string that drifts (D15, D16, D20, D21, D22). Keep overrides only for multi-component shapes (Dashboard, map routes), write those as complete code, and hold them to P1. Cost: moderate, mostly deletions and one review pass of each "Show code".

**P4. Explicit cache invalidation in the registry, and its tests.** A rejected entry stays cached until a retry, a prefetch, or a navigation clears it (E1). Add unit tests for `registry.ts`, `host.tsx`, and `use-hash.ts`: the loop in E1, the duplicate-id guard, the one-reload recovery, and `navigate`'s history state. Cost: about 15 lines plus tests.

**P5. A demo smoke test.** Render every `Demo` in jsdom, click each tab, and fail on `console.error`, `console.warn`, or a curated axe rule set (`button-name`, `aria-required-children`, `landmark-unique`, `label`). Every demo renders cleanly today, so it lands green once the a11y rows it would catch are fixed or allowlisted. Cost: small.

**P6. An a11y contract for the kit.** A required `label` on `OptionsListbox`, `SizeListbox`, `VariantListbox`, and `ValueStepper` (E3). Size labels always come from `sizeLabels` (D57). A `SizeRows` helper can replace the repeated `sizes.map(<LabeledRow>)` blocks. ui's `ChoiceListbox` (`providers/appearance/appearance-settings.tsx:44`) repeats `OptionsListbox`. A ui-internal home for both would let the docs import one. Cost: small; about 33 call sites.
