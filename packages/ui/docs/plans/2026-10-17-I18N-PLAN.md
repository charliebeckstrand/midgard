# I18N plan

This plan records how ui, `shared`, and the apps translate their text. The first step lands the mechanism, the core controls of ui, and a Spanish catalog. The later steps move the rest of the text onto the same mechanism.

## Decision

**Library.** The catalogs use FormatJS (`@formatjs/intl`). ui does not use `react-intl`, because it formats no rich text and has its own provider. A message is a descriptor with an `id`, an English `defaultMessage` in ICU syntax, and a `description` for the translator. A unit defines its descriptors next to its code with `defineMessages`, or with `defineMessage<{ … }>` for a message that takes values. Ids follow `ui.<unit>.<key>`, and the messages that many controls share use `ui.common.<key>`.

**Catalogs.** The English text lives in the source. `pnpm intl` (`scripts/intl.ts`) extracts it to `src/primitives/intl/lang/en.json` for the translators. Each translation is `src/primitives/intl/lang/<language>.json`, keyed by the same ids. `intl-catalog-boundary.test.ts` fails when `en.json` is stale, when a translation lacks an id or has an extra one, or when a translated message does not parse or changes the arguments.

**Provider.** `LocaleProvider` gives the controls an intl for its locale, with the catalog of the language subtag. A control reads it through `useIntl` in `primitives/intl`, which gives an English intl outside each provider. Only `primitives/intl` imports FormatJS. A unit takes `defineMessages` from `primitives/intl/intl-messages` and the intl types from `primitives/intl/types`, and `LocaleProvider` gives the intl through the `IntlProvider` of the primitive, which takes the locale. The primitive has its own provider and context. The [`no-formatjs-import-outside-intl`](../../../../.biome/plugins/no-formatjs-import-outside-intl.grit) Biome plugin holds this rule. An app or a package defines its messages with `defineMessages` from `ui/primitives/intl`, and gives their translations to `LocaleProvider` as `catalogs`. They merge over the catalog of ui and over the catalogs of each enclosing provider, so a provider that `RequestLocale` renders keeps the catalogs of `AppProviders`. A package extracts its own catalog with the extraction tool of ui. A missing translation shows the English default, so a catalog can grow step by step. A module with no `'use client'` renders `IntlMessage` for visible text. A static leaf reads no context. It renders `IntlMessage` for its text, and a client part for a translated attribute, such as the name of a landmark.

**Rendering.** The root layout of each app stays static and renders in `en`. The stored choice applies there after hydration. The choice lives in the `locale` cookie, with a copy in `localStorage`. A stored choice with a `cookie` (`appearance-storage.ts`) reads the cookie first in the browser, so the server and the browser read the same value. The copy in `localStorage` tells the other tabs about a change, and it gives the cookie back when the cookie expires. `RequestLocale` from `shared/locale` reads the cookie, or the `Accept-Language` header for the System choice. Each layout or page that already renders per request (the signed-in pages and the guest layouts) wraps its subtree in `RequestLocale`. The server markup of those routes is thus in the language of the reader. The docs site has no server, so it stays client only.

**`<html lang>`.** It stays `en` until the text of the apps has catalogs. Most of the text on a page is the text of the app, and a screen reader reads it with the voice of `lang`.

## Steps

1. The mechanism, the extraction script and its gate, the cookie and `RequestLocale`, and the core controls of ui with a Spanish catalog. The core controls are the Settings dialog, the close buttons of the panels, Popover, CommandPalette, Input, SearchInput, Listbox, Combobox, Confirm, Alert, Toast, Calendar, the date picker, CopyButton, PasswordInput, and Lightbox. The toast moves the focus by the `alert-close` anchor, not by the name of the button.

2. The rest of ui, one unit for each pull request: grid, query and query builder, pdf-viewer, the presets and the validation messages of the date picker and the date input, dashboard, chart, kanban, file-upload, chat, color, tag-input, and password-strength. The drag-and-drop announcements have one home: `primitives/intl/intl-reorder.ts` holds the shared sentences, the keyboard instructions, and the names of the reorder handles. The list, the query builder, Kanban, and the grid reorders use them. The grid group editor (`modules/grid/engine/grid-messages.ts`) and the dashboard keep their own sentences, because they speak of zones and cells. The pure `.ts` builders take a formatter from their client callers, as `resolveLabel` does. Pagination, Breadcrumb, and the loading leaves give their default names in the language of the reader. The loading leaves render `IntlMessage`, Breadcrumb names its `<nav>` in a client part, and Pagination reads the intl as a client component.

   An inventory after step 3 found text in units that step 2 did not name. They follow, one pull request each, before the apps: the role description that dnd-kit gives each drag grip, the layouts and the landmarks, the inputs (NumberInput, RangeSlider, Rating, SignaturePad, CreditCardInput, AddressInput, Combobox), the display components (CodeBlock, JsonTree, the Markdown table, PivotTable, Stepper, Resizable, Avatar), the form module, map, the controls of the events module, and the number and list formats of the value texts. The lines and the bug report of the events module stay in English, because they are developer data.

3. `shared`: the auth pages, the error and not-found pages, the form validators, and the default toast of a failed mutation. Add a way for an app or a package to give its own catalog to `LocaleProvider`, merged over the catalog of ui.

4. The docs app. First its text becomes clear, short, and consistent, by a style guide and a word list: the shell and the kit, the labels that come from names (page names, tab labels, example titles), the demo content, and the API reference, which is the TSDoc of ui. The docs app now has its own catalog in `src/docs/lang`, and the text of the shell and the kit is translated. The title of each example comes from its file name, so `pnpm intl` writes one catalog entry for each file name, and the title shows translated. The name of each tab comes from the `TABS` constant of its page, and `pnpm intl` writes an entry for it too. The names from the code (pages, props, and types) and the TSDoc stay English. The text of the demos stays English too, because each demo shows its own source under "Show code", and that code stays plain.

5. The apps: admin, picks, and places, each with its own catalog. Plural messages fix "1 unused recovery codes" in the two-step settings of admin.

6. `<html lang>` follows the language of the locale: an inline script before the first paint, and an update on each change.

7. Gates and size. The gates are in place: the Biome plugin above, and `default-value-boundary.test.ts`, which reads the `defaultMessage` behind a `prop ?? intl.formatMessage(…)` fallback. A translated default thus has a checked `@defaultValue` tag again. `intl-coverage-boundary.test.ts` finds literal text in the shipped tree, a format with no locale, and a number with no locale format. The size work remains: precompile the catalogs to the AST, so the apps can drop the message parser from the bundle.

8. The gateway: the error bodies of bifrost carry English `message` text, which the toasts show as is. A stable `code` for each error lets the apps show a translated message. This changes the contract in asgard `.claude/docs/midgard.md`.

The exported option lists `themeModes`, `motionModes`, `sidebarModes`, and `densityLevels` keep their English `label`, because it is public. Each option also has a `message`, which the Settings dialog shows in the language of the reader.
