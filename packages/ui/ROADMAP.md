# ui roadmap

> **Goal: code holds the import direction, the static tier, and the server entry of the foundation, and each shared behavior keeps one home.** The foundation is the code below the components and the modules. This file tracks the work that the code and the apps show is still open there.

## Status

This file covers the foundation layers of `ui`: `core`, `primitives`, `hooks`, `providers`, `recipes`, `utilities`, `layouts`, `structure`, `server`, and `types`. It also covers the gates in `src/__tests__/boundary` and the Biome plugins in `.biome/plugins`. [`src/components/ROADMAP.md`](src/components/ROADMAP.md) covers the components. Each module has its own roadmap: [`chart`](src/modules/chart/ROADMAP.md), [`chat`](src/modules/chat/ROADMAP.md), [`dashboard`](src/modules/dashboard/ROADMAP.md), [`events`](src/modules/events/ROADMAP.md), [`form`](src/modules/form/ROADMAP.md), [`grid`](src/modules/grid/ROADMAP.md), [`kanban`](src/modules/kanban/ROADMAP.md), [`map`](src/modules/map/ROADMAP.md), and [`query`](src/modules/query/ROADMAP.md).

The layers have an order. `utilities` and `types` are at the bottom, with `core` beside them. `hooks` and `primitives` read them, and a hook can read the context of a primitive. `structure`, `recipes`, `components`, `providers`, `layouts`, and `modules` sit above. The foundation has no import cycle at the file level. In `components/date-picker`, `date-picker.tsx` and `date-picker-relative.tsx` import each other.

Biome holds part of the order. The `noRestrictedImports` overrides in [`biome.json`](../../biome.json) keep components, structure, layouts, providers, kata, and kumi out of `hooks`. They keep components, structure, layouts, kumi, and kiso out of `primitives`. Kiso and kumi never import upward, and a consumer reaches a recipe only through its kata ([`src/recipes/README.md`](src/recipes/README.md) §3). No rule holds `core`, `utilities`, `types`, or `server`.

The static tier renders in React Server Components ([`REFERENCE.md`](REFERENCE.md) §2). [`static-component-boundary.test.ts`](src/__tests__/boundary/static-component-boundary.test.ts) scans a curated list of static leaves, each skeleton, and each file of `structure`. It also scans a curated list of the primitives that the leaves render through. The scan reads one file at a time.

Each behavior that many units share has one home and a gate ([`CONVENTIONS.md`](../../CONVENTIONS.md) §3.10). The import of a name comes from the file that declares it, and [`import-home-boundary.test.ts`](src/__tests__/boundary/import-home-boundary.test.ts) holds it. [`surface-index.test.ts`](src/__tests__/docs/surface-index.test.ts) holds each surface index in `docs` to its barrel. [`density-native-boundary.test.ts`](src/__tests__/boundary/density-native-boundary.test.ts), [`size-scale-boundary.test.ts`](src/__tests__/boundary/size-scale-boundary.test.ts), and [`density-geometry.test.ts`](src/__tests__/core/density-geometry.test.ts) hold density. [`biome-plugin-boundary.test.ts`](src/__tests__/boundary/biome-plugin-boundary.test.ts) proves the pattern of each Biome plugin against its fixtures.

The lazy-load hooks are one stack, not copies. `createLazyModule` in [`utilities/lazy-module.ts`](src/utilities/lazy-module.ts) holds the load. `useLazyModule` reads it, `useIdlePreload` starts it in idle time, `useIdleLoad` joins the two, and `useIntentLoad` adds the load on intent. Each layer adds one thing, so the stack stays.

## Features

1. **A span for a child of `Columns` (*P1*).** Places puts a raw `sm:col-span-2` class on many children of a `Columns` in [`form-drawer.tsx`](../../apps/places/src/components/place-form-drawer/form-drawer.tsx), [`place-form-drawer.tsx`](../../apps/places/src/components/place-form-drawer/place-form-drawer.tsx), and [`trip-form-drawer.tsx`](../../apps/places/src/components/place-form-drawer/trip-form-drawer.tsx). The class names a breakpoint by hand, and `Columns` gives the child no way to span. Mantine has `Grid.Col span`, and Chakra has `GridItem colSpan`. Add `ColumnsItem` in `structure/columns/columns-item.tsx`, with a `span` that takes `Responsive<ColumnSpan>` and `'full'`. The kata [`recipes/kata/columns.ts`](src/recipes/kata/columns.ts) writes the span as a responsive axis ([`CONVENTIONS.md`](../../CONVENTIONS.md) §5.9). A case in `__tests__/structure/columns.test.tsx`, a case in [`structure-breakpoints.test.tsx`](src/__tests__/browser/structure-breakpoints.test.tsx), a docs example, and the Places forms on the new part prove it.

2. **A public stored setting (*P2*).** Numbers keeps each game setting in a cookie with a copy in `localStorage`, which tells the other tabs ([`use-game-setting.ts`](../../apps/numbers/src/hooks/use-game-setting.ts)). Its comment says that it does what the appearance choices of `ui` do. That engine is internal in [`appearance-storage.ts`](src/providers/appearance/appearance-storage.ts) and [`use-appearance-choice.ts`](src/providers/appearance/use-appearance-choice.ts). Mantine gives `useLocalStorage`, but a cookie must hold the value so that the server paints it ([`CONVENTIONS.md`](../../CONVENTIONS.md) §3.13). Export the hook from `ui/hooks` after the move in Pattern cleanup item 2. It takes the value that the server read, so the hydration render shows it. Numbers then drops its copy, and its tests and a hook test prove the change. The change adds a public export, so surface the API for assent first ([`CLAUDE.md`](../../CLAUDE.md) §3.1).

3. **Docs pages for the layouts (*P2*).** Admin, Elections, Numbers, Picks, and the auth pages of `shared` import `ui/layouts`, and the layouts have no page. [`page-coverage.test.ts`](src/__tests__/docs/page-coverage.test.ts) says so and leaves them out. A layout can render in the main slot of another layout. `BreakpointFrame` with `viewport` gives an example its own viewport, so an example can show a whole shell. Add a page for each layout under `src/docs/pages/layouts`, after Pattern cleanup item 3. Then add `layouts` to the sections of the coverage test, and the page smoke test runs axe on each page.

## Pattern cleanup

1. **The headless and glass contexts below the components (*P2*).** [`control-frame.tsx`](src/primitives/control/control-frame.tsx) reads `useHeadless` from `providers/headless/context.ts`, and [`panel-surface.tsx`](src/primitives/panel/panel-surface.tsx) reads `useReaderSurface` from `providers/glass/context.ts`. Each primitive thus reads a layer above it. The density and direction contexts already sit in `primitives/density` and `primitives/direction`, and their providers wrap them. Move the headless context, `useSlots`, and `Shell` to `primitives/headless`. Move the glass contexts and their readers to `primitives/glass`. The provider barrels re-export the same public names, so no app changes. Pattern cleanup item 4 then holds the rule.

2. **The stored-choice engine out of `providers/appearance` (*P2*).** [`layouts/sidebar/sidebar.tsx`](src/layouts/sidebar/sidebar.tsx) and [`use-stored-locale.ts`](src/providers/locale/use-stored-locale.ts) import the stored-choice engine (`readChoice` and its relatives) from `providers/appearance`. The engine holds no appearance logic: it stores a string choice in a cookie and in `localStorage`. Its home in one provider ties the sidebar layout and the locale provider to that provider. Move the engine to `utilities/stored-choice.ts` and its hook to `hooks/use-stored-choice.ts`. The appearance choices stay in `appearance-storage.ts`. The existing appearance, locale, and sidebar tests prove that no behavior changes.

3. **One directory for each layout (*P2*).** [`CONVENTIONS.md`](../../CONVENTIONS.md) §3.3 and §3.5 give a layout one directory, as `layouts/sidebar/` has. `layouts/auth.tsx`, `layouts/stacked.tsx`, and `layouts/dashboard.tsx` are flat files. The flat files keep the page coverage test from reading the layouts as units. Move each to `layouts/<name>/<name>.tsx` with a barrel. The `ui/layouts` entry keeps each export, so no app changes.

4. **A gate for the import direction of the foundation (*P2*).** No rule keeps `core`, `utilities`, or `types` from importing a hook, a primitive, or a component. The `hooks` and `primitives` overrides do not name `modules`, and the `primitives` override does not name `providers`. Add `noRestrictedImports` overrides for `core`, `utilities`, and `types` in [`biome.json`](../../biome.json), in the form of the `hooks` override. Add `modules` to the `hooks` and `primitives` groups, and add `providers` to the `primitives` group after item 1. Add `import-cycle-boundary.test.ts`, which fails on a cycle of value imports in `src`. Break the `date-picker` cycle first. State the order of the layers in [`REFERENCE.md`](REFERENCE.md) in the same commit.

5. **The static and server gates walk the import graph (*P2*).** The static gate reads one file at a time and keeps a hand list of primitives. [`REFERENCE.md`](REFERENCE.md) §2 says that a transitive client pull shows only at the build of an app. [`SERVER.md`](docs/SERVER.md) says that each file of `ui/server` renders no React and has no `'use client'`, and no test holds that. `ui/server` reaches `providers/appearance`, `providers/density`, and the events engine. Add a walker of the value imports to `__tests__/helpers`, as [`grid-lazy-boundary.test.ts`](src/__tests__/boundary/grid-lazy-boundary.test.ts) walks its graph. The static gate walks from each static file, stops at a `'use client'` file, and applies its checks to each file that it reaches. The hand list of primitives then goes. A server gate walks from `server/index.ts` and fails on a `'use client'` file, a `.tsx` file, or a value import of `react`.

6. **The composed keys in the spread-order gate (*P2*).** [`CONVENTIONS.md`](../../CONVENTIONS.md) §3.9 says that a component destructures a handler or a `style` and merges it. It also says that no gate holds that part. [`spread-order-boundary.test.ts`](src/__tests__/boundary/spread-order-boundary.test.ts) already finds an internal `ref` that replaces a consumer `ref`. It reads the parameter patterns to know whether the spread still carries the key. Apply the same check to `style` and to each `on*` handler. An element that writes such a key after a spread that still carries it drops the value of the consumer. The case must start clean. A break that it finds gets its fix in the same pull request.

7. **A plugin for the reads that the React Compiler removes (*P2*).** [`CONVENTIONS.md`](../../CONVENTIONS.md) §10.7 forbids a bare property read to flush the style, a `void key` read, and a `biome-ignore` of the dependency lint. No gate holds them, and a break gives no error at run time. Add a Grit plugin that flags an expression statement that reads only `offsetHeight`, `offsetWidth`, or `getBoundingClientRect()`, or that is `void` of a name. [`force-style-flush.ts`](src/utilities/force-style-flush.ts) is its one exclusion. Add a case to a boundary test that fails on `biome-ignore lint/correctness/useExhaustiveDependencies` in the source of `ui`. The source has no break today.

8. **Proof of the scope of each Biome plugin (*P2*).** [`CONVENTIONS.md`](../../CONVENTIONS.md) §10.10 and the header of [`biome-plugin-boundary.test.ts`](src/__tests__/boundary/biome-plugin-boundary.test.ts) say that the gate proves the pattern and not the `includes`. A plugin with a wrong glob never runs, and nothing fails. A copy of `biome.json` and `.biome` in a temporary root applies each override by the path of a fixture. A probe at `packages/ui/src/hooks/` gets the clamp diagnostic, and the excluded `packages/ui/src/utilities/clamp.ts` gets none. For each plugin, write one fixture in its scope and one out of it. Lint the temporary root with the real config.

## Performance

1. **A bench for the open of a modal overlay (*P2*).** `Overlay` in [`primitives/overlay`](src/primitives/overlay) moves the focus, locks the scroll, seals the page with `inert`, and records its layer and its fade. The seal touches each element outside the panel, so its cost grows with the page. The browser suite benches the popover, the menu, and the tooltip, and no bench opens a Dialog, a Sheet, or a Drawer. Add `__benchmarks__/browser/overlay-open.bench.tsx`. It opens and closes a Dialog over a page of many siblings. Each sample settles on the focus in the panel, or on the return of the focus. Record the findings in a dated section of [`__benchmarks__/browser/README.md`](src/__benchmarks__/browser/README.md) ([`CONVENTIONS.md`](../../CONVENTIONS.md) §12.6).

## Accessibility and testing

1. **The static layouts in the static gate (*P1*).** [`LAYOUTS.md`](docs/LAYOUTS.md) declares `AuthLayout` and the `StackedLayout` family static. Server modules render them, such as [`page-frame.tsx`](../../apps/elections/src/components/page-frame/page-frame.tsx) in Elections and [`game-frame.tsx`](../../apps/numbers/src/components/game-frame/game-frame.tsx) in Numbers. The static gate reads `components`, `structure`, and `primitives`, and no file of `layouts`. A hook in `layouts/stacked.tsx` thus passes each gate of `ui` and fails at run time in an app. Add the two static layout files to the scan of [`static-component-boundary.test.ts`](src/__tests__/boundary/static-component-boundary.test.ts).

2. **A skip link in `SidebarLayout` (*P2*).** A reader with a keyboard tabs through each item of the sidebar before the content. The landmarks meet WCAG 2.4.1, but they help only a reader with a screen reader. GOV.UK Frontend and the U.S. Web Design System give a skip link that shows when it has the focus. Add one to [`layouts/sidebar/sidebar.tsx`](src/layouts/sidebar/sidebar.tsx), first in the tab order, with its text from `defineMessages`. A layout in the main slot of another layout renders none, because `useLandmark` tells it that a main encloses it. A browser test proves that the first Tab shows the link, and that Enter moves the focus to the main slot.

3. **Seam tests for the overlay registries and `useStableValue` (*P2*).** [`overlay-layers.ts`](src/utilities/overlay-layers.ts) decides whether an overlay covers the anchor of a float. [`floating-portal-registry.ts`](src/utilities/floating-portal-registry.ts) decides whether a press landed in a surface that opened from inside a container. Each is a synchronous seam, and only browser tests of whole components reach them, such as [`floating-covered-by-overlay.test.tsx`](src/__tests__/browser/floating-ui/floating-covered-by-overlay.test.tsx). [`use-stable-value.ts`](src/hooks/use-stable-value.ts) holds the identity that the memos of the grid and the map read ([`CONVENTIONS.md`](../../CONVENTIONS.md) §10.7), and it has no test of its own. Add a test file for each under `__tests__/utilities` and `__tests__/hooks` ([`CONVENTIONS.md`](../../CONVENTIONS.md) §10.3).

## Not planned

- The `popover` attribute, CSS anchor positioning alone, or `showModal()` for the floating and overlay shells. A native close cannot wait for an exit animation in each engine, `showModal()` does not lock the scroll, and it makes the toasts inert ([`PRIMITIVES.md`](docs/PRIMITIVES.md)).

- A move of `AppearanceSettings` out of `providers`. `UIProvider` also renders the hosts of the toast and the confirm, so the providers layer sits above the components in each case. The move also breaks a public import path for no gain.

- A registry through which a module adds its marks to `rootMarks`. The events module is the one such module, and `ui/server` reaches only its pure engine files. Pattern cleanup item 5 holds that the server graph stays pure.

- One hook in place of `useIdleLoad`, `useIntentLoad`, `useLazyModule`, and `useIdlePreload`. Each adds one layer over one `LazyModule`, and the apps import the two public ones.

- One density module in place of `core/density`, `primitives/density`, and `providers/density`. They are three layers: the Tailwind plugin and the steps, the context, and the friendly levels of a provider.
